# 什么是段错误? 什么情况下会遇到段错误? 遇到段错误怎么解决?

## 什么是段错误?

**段错误(Segmentation fault, segfault)**: 程序访问了不允许访问的内存地址, 操作系统内核发送**SIGSEGV**信号把程序直接崩溃终止

> 内存是分段管理：代码段、数据段、栈、堆。段错误本质：**内存访问越权**，访问不属于你的进程内存、访问受保护内存。

## 那种情况会遇到段错误?

- 空指针解引用

  ```c
  int *p = NULL;
  *p = 10;   // 给空指针赋值，segfault
  ```

- 野指针

  ```c
  int *p;      // 局部变量，未初始化，里面是随机垃圾地址
  *p = 100;
  ```

  ```c
  int *p = malloc(4);
  free(p);
  *p = 5;  // 悬空指针，大概率段错误
  ```

- 数组越界访问

  ```c
  int arr[3] = {1,2,3};
  arr[100] = 99; // 越界，破坏栈，可能段错误
  ```

  > 注意：数组越界**不一定立刻段错误**，如果刚好踩在本进程合法内存，只会静默篡改数据（缓冲区溢出 bug）

- 修改字符串常量（只读代码段）

  ```c
  char *s = "hello";
  s[0] = 'H';  // ❌ segfault！字符串常量只读
  ```

  > 改为 `char s[] = "hello";` 放到栈上就可以修改

- 栈溢出（递归太深 / 局部大数组）

  ```c
  void func(){
      char buf[1024*1024*10]; // 栈上申请10MB大数组，栈爆，段错误
      func(); // 无限递归，栈不断压栈，栈溢出segfault
  }
  ```

  > 函数局部变量在栈，栈空间很小（一般几 MB）

- 指针强制类型转换错误，访问错误地址

  ```c
  unsigned long addr = 0x1234;
  int *p = (int*)addr;
  *p = 1; // 直接访问随便写的虚拟地址，段错误
  ```

- 多线程场景

  - 线程操作已经销毁的变量
  - 共享指针被一个线程free, 另一个线程解引用

  > 区分：
  >
  > - **段错误 SIGSEGV**：访问非法虚拟内存地址
  > - **总线错误 SIGBUS**：地址合法，但访问对齐不支持（ARM 平台多见，x86 很少）

## 遇到段错误怎么解决?

- core dump核心转储

​	程序崩溃生成core文件, 保存崩溃瞬间内存\调用栈,

1. 打开core生成大小限制

   ```bash
   ulimit -c unlimited   # 当前shell允许生成core文件
   ```

2. gdb调试core文件

   ```bash
   gdb ./a.out core.12345
   # 进入gdb后直接输入
   bt    # backtrace，打印崩溃调用栈，直接看到在哪一行炸
   ```

   > bt直接看到函数调用链, 定位崩溃行号

3. gcc看调试信息

   ```bash
   gcc -g test.c -o test
   ```

   > 不加-g, core 只能看到函数名，看不到源码行号

- gdb直接跑程序复现

  ```bash
  gdb ./test
  run   # 执行程序，等待复现段错误
  # 崩溃后
  bt        # 看调用栈
  info locals # 看崩溃函数局部变量
  print p     # 打印指针的值，看是不是NULL/野指针
  ```

- AddressSanitizer

  现代 gcc/clang 自带，专门检测内存错误：野指针、越界、use‑after‑free，**直接打印出错源码行，不用自己分析 core**。

  编译加参数：

  ```bash
  gcc -g -fsanitize=address test.c -o test
  ./test
  ```

  > 一旦内存错误，直接输出完整报告：哪一行，什么错误（use after free /heap‑buffer‑overflow）。
  >
  > 缺点：程序运行会变慢、内存占用变高，适合测试阶段，生产不要开。

- 日志打印

  > 在关键函数前后打印日志，缩小崩溃范围。
  >
  > ⚠️ 注意：printf 有缓冲区，崩溃前缓冲区没刷入磁盘，日志丢失；需要 `fflush(stdout);`。

- valgrind

  ```bash
  valgrind ./test
  ```

  > 可以检测：越界读写、内存泄漏、悬空指针解引用。缺点速度很慢，大程序会卡顿。

# const和define的区别

- 预处理器宏与变量的区别

  > #define 是一个预处理器指令，用于在编译前将某些文本替换为指定的值。它没有类型信息，是简单的文本替换。#define 声明的常量不会占用内存，它只是在预处理阶段做替换。const 是C语言中的一个类型修饰符，用来声明常量，它会为常量分配内存并指定类型。常量的值在程序运行期间不可修改。

- 类型安全

  > #define 没有类型信息，编译器无法检查类型。因此，它在某些情况下可能导致类型不匹配的问题。const 声明的常量具有类型，可以利用编译器的类型检查来避免错误。

- 作用域

  > #define 声明的常量是全局的，通常在**整个文件**中有效，甚至跨函数调用，除非使用#undef来取消定义。const 声明的常量遵循变量的作用域规则，可以限制常量的作用范围。

#define 更适用于简单的常量替换、条件编译和宏函数，它不具备类型检查，灵活性高，但容易引发错误。const 更适用于需要类型安全、具有作用域限制的常量声明，特别是在涉及到变量和复杂数据类型时。

# 结构体和联合体的区别

1. 结构体 (struct) 是一种聚合数据结构，它能够将不同类型的数据组合在一起，每个成员都有独立的内存空间。
2. 联合体 (union) 也是一种聚合数据结构，它与结构体类似，但联合体的所有成员共享同一块内存空间，即所有成员共用同一内存地址，只有一个成员能够在任何时刻存储值。
3. 结构体适用于需要同时存储多个不同数据类型的情况，而联合体适用于在同一内存空间中存储不同类型的数据，但一次只能使用其中一个成员。

# sizeof和strlen的区别

| 项目       | sizeof                        | strlen                     |
| ---------- | ----------------------------- | -------------------------- |
| 性质       | 运算符                        | 库函数                     |
| 计算时机   | 编译期（变长数组 VLA 运行期） | 运行时循环遍历             |
| 计算内容   | 占用内存字节总数              | `\0`之前字符个数，不含`\0` |
| 依赖`\0`？ | 不需要                        | 必须依靠`\0`终止           |
| 参数       | 任意数据类型                  | char* 字符串首地址         |
| 数组名     | 不退化（sizeof (数组名)）     | 数组名传入直接退化指针     |

# typedefine和define的区别

- typedefine

  - 是**C 语言关键字**，编译阶段处理，用来给已有数据类型起别名

  - **编译时**，由编译器识别类型

  - 指针场景下

    ```c
    typedef int *PINT;
    PINT a,b;   //a、b都是int*指针
    ```

  - 遵循 C 变量作用域，写在函数内局部有效，全局则全局有效

  - 可以用于结构体、数组，定义复杂类型别名

- define

  - 是**预处理指令**，预处理阶段做简单文本替换，不是类型定义

  - **预处理阶段**，单纯字符串替换，不做语法检查

  - 指针场景下:

    ```c
    #define PINT2 int *
    PINT2 c,d;  //文本替换：int *c,d;  c是指针，d只是int变量
    ```

  - 从定义处开始，**直到文件末尾，不受函数大括号限制**，除非`#undef`取消

  - 只是文本替换，容易出现优先级错误
  
  # 什么是内存泄漏?怎么避免内存泄漏

程序使用`malloc`等从堆上申请一块内存，**程序不再使用这块内存了，但是没有调用`free()`释放**； 这块堆内存就一直被程序占用，操作系统不能回收给别的程序使用。随着程序不断运行，堆积越来越多无法回收内存 → **内存泄漏 (memory leak)**
