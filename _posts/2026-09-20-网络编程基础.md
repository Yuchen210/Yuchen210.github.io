# OSI模型

从上到下:

- 应用层	HTTP协议等
- 表示层	ASCII码
- 会话层	SSL/TLS
- 传输层	TCP, UDP
- 网络层	IP协议, 路由器
- 数据链路层	MAC地址, 交换机
- 物理层	网线, 光纤, 集线器

# TCP/IP模型

从上到下:

- 应用层	HTTP, FTP, DNS
- 传输层	TCP, UDP
- 网络层	IP, ICMP
- 网络接口与物理层	以太网

# TCP/IP与OSI对比

| OSI七层模型 | TCP/IP四层模型       | 核心功能                   | 典型协议/技术            |
| ----------- | -------------------- | -------------------------- | ------------------------ |
| 应用层      | 应用层               | 直接面向用户，提供网络服务 | HTTP、FTP、SMTP、DNS     |
| 表示层      | （合并至应用层）     | 数据格式转换、加密/压缩    | JPEG、SSL/TLS、ASCII     |
| 会话层      | （合并至应用层）     | 建立/维护/终止会话连接     | NetBIOS、RPC             |
| 传输层      | 传输层               | 端到端可靠传输、流量控制   | TCP（可靠）、UDP（高效） |
| 网络层      | 网络层               | 路由选择、IP寻址           | IP、ICMP、ARP            |
| 数据链路层  | 网络接口层           | 相邻节点帧传输、错误检测   | Ethernet、Wi-Fi、MAC地址 |
| 物理层      | （合并至网络接口层） | 物理介质传输比特流         | 光纤、网线、无线电波     |

# TCP协议

## 面向连接

## 三次握手

```
客户端                            				服务端
CLOSED                          			  LISTEN
   			|  1. SYN seq=x                 |
SYN_SENT    |------------------------------>| SYN_RCVD
   			|                               |
   			|  2. SYN+ACK seq=y,ack=x+1     | 
   			|<------------------------------|
   			|                               |
   			|3. ACK ack=y+1                 |
ESTABLISHED |------------------------------>| ESTABLISHED
                     
```

## 四次挥手

```
客户端                            				  服务端
ESTABLISHED                     			    ESTABLISHED
			| 1. FIN seq=u                    |
FIN_WAIT_1	|-------------------------------->| 
			|                   2. ACK ack=u+1| CLOSE_WAIT
			|<--------------------------------|
FIN_WAIT_2  |                      			  |
			|          	        S继续发送剩余数据|
			|                     3. FIN seq=v| 
			|<--------------------------------|
TIME_WAIT	| 4. ACK ack=v+1                  | LAST_ACK
(2MSL)		|-------------------------------->| CLOSED

等待2MSL → CLOSED
Linux下MSL默认30s
RFC建议MSL 60s
```

建立连接时，服务端 SYN 和 ACK 可以合并成一个报文（第二次握手）。 关闭连接不行： 收到对方 FIN 时，服务端**可能还有业务数据没发完**，不能立刻发送 FIN。

- 第二步：先回复 ACK 确认收到 FIN（此时继续传剩余数据）
- 等数据全部发完，第三步才发送 FIN。

> ACK 和 FIN 不能合并，所以必须分成两段报文，总共四次。

- 可靠传输

  丢包重传: 丢失的数据包会重新进行发送, 直到收到为止

  数据排序: 将乱序的数据重新排列有序

- 流量控制

​	滑动窗口: 根据接收方能力动态调整发送速度

# 物理层与MAC地址

物理层关注信号传输质量, 不识别设备IP地址

## MAC层(介质访问控制)

- 控制设备如何访问共享物理介质
- 定义帧的封装格式, 包括源/目标MAC地址
- 实现冲突检测与避免

## LLC子层(逻辑链路控制)

- 提供逻辑链路标识, 通过SAP服务访问点
- 实现流量控制与错误恢复, 如滑动窗口协议

## 工作流程

网络数据包-> 数据链路层

数据链路层-> LLC添加控制信息, MAC添加头尾 -> 物理层

物理层 -> 将帧转换为比特流进行传输

## MAC地址

- 48位, 十六进制表示: 00:1A:2B:3C:4D:5E

## IP数据包结构

![IP数据包结构体图](/../assets/pictures/IP数据包结构体图.png)

1. **Version (4bit) 版本**：IPv4 固定 = 4；IPv6=6

2. **IHL (4bit) 首部长度**：单位 4 字节；最小值 5 → 20 字节（无选项）；最大 15 → 60 字节

3. **DSCP+ECN (8bit，原 TOS 服务类型)**：QoS、拥塞标记

4. **Total Length (16bit) 总长度**：IP 头 + 数据总字节，最大 65535 字节

5. **Identification (16bit) 标识**：同一个 IP 包分片，ID 相同，用于重组分片

6. **Flags (3bit)** 标志

   - bit0：保留
   - bit1：DF (Don't Fragment)，1 = 禁止分片
   - bit2：MF (More Fragment)，1 = 后面还有分片

7. **Fragment Offset (13bit) 片偏移**：分片在原始数据包中的位置，**单位 8 字节**

8. **TTL (8bit) 生存时间**：每经过一台路由器 - 1，减到 0 丢弃，防止环路

9. **Protocol (8bit)** 协议号

   上层是什么协议

   - 1=ICMP，6=TCP，17=UDP

10. **Header Checksum (16bit) 首部校验和**：**只校验 IP 头部，不校验后面的数据**，路由器每转发一次重新计算

11. **源 IP 地址 32bit**：发送方 IP

12. **目的 IP 地址 32bit**：接收方 IP

13. **Options+Padding**：可选字段，0~40 字节，不足 4 字节填充 0 对齐

## IPV4地址分类

- A类: 8位掩码, 0.0.0.0 ~ 127.255.255.255
- B类: 12位掩码, 128.0.0.0 ~ 191.255.255.255
- C类: 24位掩码, 192.0.0.0 ~ 223.255.255.255
- D类: 组播, 224.0.0.0 ~ 239.255.255.255
- E类: 保留, 240.0.0.0 ~ 255.255.255.255

## 私有地址

- A类: 10.0.0.0 ~ 10.255.255.255
- B类: 172.16.0.0 ~ 172.31.255.255
- C类: 192.168.0.0 ~ 192.168.255.255 

## IPV6

- 地址长度: 128位, 理论数量≈ 3.4x10383.4x1038
- 简化头部: 固定40字节, 取消校验和
- 地址类型: 单播, 组播, 任播
- 示例: 2001:0db8:85a3::8a2e:0370:7334（::表示连续0的缩写）

# 传输层与端口

## 功能: 端到端通信

两大核心服务:

- TCP可靠传输
- UDP高效传输

## 端口

16位整数（0~65535），与IP地址共同组成套接字（Socket），唯一标识通信端点

核心作用:

- 服务标识：客户端通过端口号访问特定服务（如HTTP默认80端口）
- 并发支持：服务端通过不同端口同时处理多个请求

### 端口分类

- 公认端口 0 ~ 1023	系统级服务
- 注册端口 1024 ~ 49151	用户级应用, 需要向IANA注册
- 动态端口 49152 ~ 65535	客户端临时使用, 操作系统分配

### 常见端口示例

ssh	22

http	80

https	443

DNS	53

MySQL	3306

# 架构模式

## C/S架构(Client-Server)

- 客户端：发起请求（如微信桌面端）
- 服务器：集中处理请求并响应（如腾讯聊天服务器）

优点: 

高性能：客户端可分担计算压力（如游戏本地渲染）

功能定制化：客户端可深度优化用户体验

缺点:

维护成本高：需为不同平台开发客户端（Windows、macOS、Android等）

升级困难：用户需手动更新客户端版本

## B/S架构(Browser-Server)

- 浏览器：统一客户端（如Chrome、Firefox）
- 服务器：提供Web服务（如Nginx、Apache）

优点:

跨平台：任何设备通过浏览器即可访问

易维护：服务端更新即全网生效

缺点

性能受限：复杂计算依赖服务端（如在线视频编辑）

功能限制：浏览器沙箱环境限制硬件访问（如摄像头需授权）

# 套接字与字节序

## 套接字类型

- 流式套接字

  （SOCK_STREAM）TCP 可靠、面向连接、双向字节流 网页、文件传输

- 数据报套接字

  （SOCK_DGRAM）UDP 不可靠、无连接、数据包独立 实时音视频、DNS查询

- 原始套接字

​	  (SOCK_RAW）自定义 直接访问底层协议（如ICMP） 网络诊断工具（ping）

## 大小端序

- 大端序（网络字节序）：高位字节在前（人类书写习惯，数据的高字节保存在内存的低地址中，而数据的低字节，保存在内存的高地址中），比如0x1234 存储为 12 34
- 小端序（主机字节序）：低位字节在前（x86/ARM架构，数据的高字节保存在内存的高地址中，而数据的低字节，保存在内存的低地址中），比如0x1234 存储为 34 12

# TCP通信

## 服务端创建流程

1. 创建流式套接字
2. 填充服务器的网络信息结构体
3. 将套接字与服务器网络信息绑定
4. 将套接字设置为被动监听状态
5. 阻塞等待客户端连接
6. 收发数据
7. 关闭套接字

## 客户端创建流程

1. 创建流式套接字
2. 填充服务器的网络信息结构体
3. 与服务器建立连接
4. 收发数据
5. 关闭套接字

## socket函数

- 头文件

  #include <sys/socket.h>

- 原型

  int socket(int domain, int type, int protocol);

- 功能

  创建socket

- 参数

  domain 就是通信域，也可以说是协议族，常见通信域如下：

  > AF_INET 	IPV4
  > AF_INET6	IPV6
  > AF_PACKET 	原始套接字使用
  > AF_UNIX	本地通信
  > AF_LOCAL	本地通信

  type 表示socket的类型，常用的socekt类型如下：

  > SOCK_STREAM	TCP使用
  > SOCK_DGRAM	UDP使用
  > SOCK_RAW	原始套接字

  protocol 表示附加协议 无附加协议填0（自动选择默认协议）

- 返回值

  成功	返回套接字（文件描述符-非负整数）

  失败	返回-1 （并重置错误码）

## bind函数

- 头文件

  #include <sys/socket.h>

- 原型

  int bind(int sockfd, const struct sockaddr *addr, socklen_t addrlen);

- 功能

  将socket和地址进行绑定

- 参数

  sockfd	就是文件描述符（由socket函数返回）
  addr 	表示地址结构体指针（const struct sockaddr*），指向要绑定给sockfd的协议地址，该结构体根据创建socket时的协议族不同而不同，这里以IPV4为例:

  ```c
  // 通用接口, sa_data[14]是一块原始缓冲区，把端口 + IP 地址打包放在里面，人类很难直接赋值。
  // 不能直接手动填充，只是用来做类型强转。
  struct sockaddr {
      sa_family_t sa_family;    // 地址族，AF_INET / AF_UNIX
      char        sa_data[14];  // 地址+端口，原始二进制数据
  };
  
  // 专门给 IPv4 使用！字段拆分清晰，我们代码里手动填充这个结构体 sin_zero[8]：填充占位，必须置 0，目的是保证 sizeof(sockaddr_in) == sizeof(sockaddr) 强转安全
  struct sockaddr_in {
      sa_family_t    sin_family;   // 地址族：固定 AF_INET
      in_port_t      sin_port;     // 端口，网络字节序（大端）
      struct in_addr sin_addr;     // IPv4地址
      char           sin_zero[8];  // 填充0，为了让大小和sockaddr保持一致
  };
  
  struct in_addr {
      uint32_t s_addr;  // IPv4地址，网络字节序
  };
  ```

  addrlen 表示地址的长度

- 返回值

  成功	返回0

  失败	返回-1 （并重置错误码）

## 示例代码

```c
// Server端
#include <stdio.h>
#include <sys/socket.h>
#include <netinet/in.h>
#include <string.h>
#include <arpa/inet.h>
#include <unistd.h>

int main(int argc, const char *argv[])
{
    // 创建socket
    int serverSocketFd = 0;
    serverSocketFd = socket(AF_INET, SOCK_STREAM, 0);
    if (serverSocketFd == -1)
    {
        perror("Create socket failed");
        return -1;
    }
    printf("Socket create succeed: fd=%d\n", serverSocketFd);

    // 填充服务器的网络信息结构体
    struct sockaddr_in serverInfo;
    memset(&serverInfo, 0, sizeof(serverInfo));
    serverInfo.sin_family = AF_INET;
    serverInfo.sin_addr.s_addr = inet_addr("192.168.116.100");
    serverInfo.sin_port = htons(8888);
    printf("Server info set succeed, address:%s, port:%d\n", "192.168.116.100", ntohs(serverInfo.sin_port));

    // 绑定套接字与服务器网络
    int bindReturn = 0;
    // bind参数: __fd:套接字文件描述符, __addr: 强制类型转换的sockaddr结构体,见笔记, __len: 结构体的大小
    bindReturn = bind(serverSocketFd, (struct sockaddr *)&serverInfo, sizeof(serverInfo));
    if (bindReturn == -1)
    {
        perror("Bind socket with server address failed");
        return -1;
    }
    printf("Bind socket with server address \n");

    // 将服务端设置为监听状态
    // __fd:套接字文件描述符, __n:套接字队列最大数
    int listenReturn = 0;
    listenReturn = listen(serverSocketFd, 5);
    if (listenReturn == -1)
    {
        perror("Set socket to listen mode failed");
        return -1;
    }
    printf("Set socket to listen mode address \n");
    

    // 等待客户端连接
    while (1)
    {
        printf("Waiting for client to connect\n");
```

## TCP沾包

### **原因：**

1. **面向字节流特性**：TCP 将数据视为连续字节流，不保留消息边界。
2. **缓冲区机制**：发送方缓冲区可能合并多个小数据包，接收方缓冲区积累数据。
3. **接收方读取策略**：接收方未按发送方的数据包边界读取，导致多包合并。

### **解决方案：**

1. **定长数据包**：规定每个数据包长度固定，接收方按固定长度读取。
2. **分隔符标识**：在数据包末尾添加特殊分隔符（如 \r\n），接收方按分隔符拆分。
3. **首部长度字段**：在数据包首部添加长度字段，接收方先读长度再读数据。
4. **应用层消息边界**：在应用层协议中定义消息格式，明确包边界。

## recvfrom函数

- 头文件

  #include <sys/socket.h> 

  #include <sys/types.h>

- 原型

  ssize_t recvfrom(int sockfd, void *buf, size_t len, int flags, struct sockaddr *src_addr, socklen_t *addrlen);

- 功能

  从网络中接收UDP数据包

- 参数

  sockfd	表示客户端的socket套接字

  buf	要接收的数据首地址

  len	可接受数据的最大长度

  flags	控制选项（如MSG_DONTWAIT非阻塞，MSG_PEEK窥视数据，0阻塞）

  src_addr	源地址，获取发送方的信息

  addrlen	地址长度

- 返回值

  成功	返回接收字节数

  失败	返回-1 （并重置错误码）

## sendto函数

- 头文件

  #include <sys/socket.h> 

  #include <sys/types.h>

- 原型

  ssize_t sendto(int sockfd, const void *buf, size_t len, int flags, const struct sockaddr *dest_addr, socklen_t addrlen);功能

- 功能

  从网络中接收UDP数据包

- 参数

  sockfd	表示客户端的socket套接字

  buf	要发送的数据首地址

  len	数据大小

  flags	控制选项（如MSG_DONTWAIT非阻塞，MSG_PEEK窥视数据，0阻塞）

  dest_addr	目的地址，数据将要发向哪一个ip地址的主机

  addrlen	地址长度

- 返回值

  成功	返回发送字节数

  失败	返回-1 （并重置错误码）

## setsockopt函数

- 头文件

  #include <sys/socket.h> 

- 原型

  int setsockopt(int sockfd, int level, int optname, const void *optval, socklen_t optlen);

- 功能

  系统调用, 修改套接字相关的配置

- 参数

  sockfd	目标套接字描述符，表示需要配置的套接字

  level	选项层级

  > SOL_SOCKET 	通用套接字
  >
  > IPPROTO_IP	IPV4层选项
  >
  > IPPROTO_TCP	TCP专属选项
  >
  > IPPROTO_UDP	UDP专属选项

  optname	选项名称, 常用选项如下:

  > **SOL_SOCKET层级**
  >
  > **SO_REUSEADDR**	端口复用:	
  >
  > ```
  > int opt = 1;
  > setsockopt(fd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));
  > ```
  >
  > **SO_RCVBUF/SO_SNDBUF**	收发缓冲区大小:	
  >
  > ```
  > int bufsize = 4096;
  > setsockopt(fd, SOL_SOCKET, SO_RCVBUF, &bufsize, sizeof(bufsize)); //接收缓冲区
  > setsockopt(fd, SOL_SOCKET, SO_SNDBUF, &bufsize, sizeof(bufsize)); //发送缓冲区
  > ```
  >
  > **SO_RCVTIMEO/SO_SNDTIMEO**	阻塞socket设置超时:	
  >
  > ```
  > struct timeval tv;
  > tv.tv_sec = 3;  //秒
  > tv.tv_usec = 0; //微秒
  > setsockopt(fd, SOL_SOCKET, SO_RCVTIMEO, &tv, sizeof(tv));
  > ```
  >
  > **IPPROTO_TC专属**
  >
  > **TCP_NODELAY**	关闭Nagle算法, 小包不缓存, 减轻TCP粘包
  >
  > ```
  > int opt = 1;
  > setsockopt(fd, IPPROTO_TCP, TCP_NODELAY, &opt, sizeof(opt));
  > ```
  >
  > **TCP_KEEPALIVE**	TCP保活
  >
  > ```
  > int alive = 1;
  > setsockopt(fd, IPPROTO_TCP, SO_KEEPALIVE, &alive, sizeof(alive));
  > ```
  >
  > **IPPROTO_IP**
  >
  > IP_ADD_MEMBERSHIP	加入组播, UDP组播用
  >
  > ```
  > struct ip_mreq mreq;
  > setsockopt(fd, IPPROTO_IP, IP_ADD_MEMBERSHIP, &mreq, sizeof(mreq));
  > struct ip_mreq
  > {
  >  struct in_addr imr_multiaddr;  // 【要加入的组播组IP】
  >  struct in_addr imr_interface; // 【本机网卡IP：在哪张网卡加入这个组】
  > };
  > ```
  >
  > IP_DROP_MEMBERSHIP	离开组
  >
  > IP_MULTICAST_TTL	设置TTL, 控制组播跨网段, 默认1(仅本网段)
  >
  > IP_MULTICAST_IF	指定发送组播的网卡
  >
  > IP_MULTICAST_LOOP	是否开启组播回环（本机发送组播，本机是否收到）

  optval	指向选项值的指针，类型和长度需与 optname匹配

  optlen	optval指向的数据长度

- 返回值

  成功	返回0

  失败	返回非零数据

# 并发服务器

## select

- 头文件 

  #include <sys/select.h> 

  #include <sys/types.h> 

  #include <unistd.h>

- 原型 

  int select (int nfds, fd_set *readfds, fd_set *writefds, fd_set *exceptfds, struct timeval *timeout);

- 功能 

  同步 IO 多路复用，监视多个文件描述符，等待其中一个或多个 fd 就绪（可读 / 可写 / 异常）

- 参数 

  nfds	待监听的 fd 中最大文件描述符值 + 1 

  readfds	读文件描述符集合，监听 fd 是否可读 

  writefds	写文件描述符集合，监听 fd 是否可写 

  exceptfds	异常文件描述符集合，监听 fd 是否发生异常 

  timeout	超时时间，NULL 永久阻塞；0 非阻塞，立即返回；大于 0 等待指定时长

- 返回值 

  成功	返回就绪 fd 的总个数 超时	返回 0 

  失败	返回 - 1（并设置错误码）

### fd_set

- 头文件 

  #include <sys/select.h>

- 原型 

  typedef __fd_mask fd_mask; __

  #define __NFDBITS (8 * sizeof (fd_mask)) __

  typedef struct { 

  ​	fd_mask fds_bits [__FD_SETSIZE /__NFDBITS]; 

  } fd_set;

- 功能 

  select 使用的文件描述符集合类型，用位图方式保存待监听 fd

- 配套宏 

  FD_ZERO (fd_set *fdset)       清空集合，全部置 0 

  FD_SET (int fd, fd_set *fdset) 将 fd 加入集合 

  FD_CLR (int fd, fd_set *fdset) 将 fd 从集合移除 

  FD_ISSET (int fd, fd_set *fdset) 判断 fd 是否在就绪集合

- 注意 

  默认最大监听 fd 数量 __FD_SETSIZE=1024，是 select 硬限制

### 示例代码

```c
#include <stdio.h>
#include <sys/socket.h>
#include <sys/types.h>
#include <unistd.h>
#include <netinet/in.h>
#include <arpa/inet.h>
#include <string.h>
#include <sys/select.h>
#include <stdbool.h>

#define SERVER_IP_ADDRESS "192.168.116.100"
#define SERVER_IP_PORT 8888
#define BUFFER_SIZE 128

int main(int argc, const char *argv[])
{
    // 创建套接字
    int serverSocketFd = 0;
    serverSocketFd = socket(AF_INET, SOCK_STREAM, 0);
    if (serverSocketFd == -1)
    {
        perror("Create socket failed");
        return -1;
    }
    printf("Create socket succeed, serverSocketFd:%d\n", serverSocketFd);

    // 创建服务器网络结构体
    struct sockaddr_in serverInfo;
    socklen_t serverLen = sizeof(serverInfo);
    memset(&serverInfo, 0, serverLen);
    serverInfo.sin_family = AF_INET;
    serverInfo.sin_addr.s_addr = inet_addr(SERVER_IP_ADDRESS);
    serverInfo.sin_port = htons(SERVER_IP_PORT);

    // 绑定套接字与服务器信息
    if (bind(serverSocketFd, (struct sockaddr *)&serverInfo, serverLen) == -1)
    {
        perror("Bind server with IP failed");
        close(serverSocketFd);
        return -1;
    }
    printf("Bind server with IP succeed, %s:%d\n", SERVER_IP_ADDRESS, SERVER_IP_PORT);

    // 设置服务端socket监听
    if (listen(serverSocketFd, 3) == -1)
    {
        perror("Server listen failed");
        close(serverSocketFd);
        return -1;
    }
    printf("Server listening on %s:%d\n", SERVER_IP_ADDRESS, SERVER_IP_PORT);

    // 创建监听集合
    fd_set readFd;
    fd_set modifyFd;
    int maxfd = serverSocketFd;

    FD_ZERO(&readFd);
    FD_ZERO(&modifyFd);
    FD_SET(serverSocketFd, &readFd);

    // 创建客户端信息, 用于处理连接
    struct sockaddr_in client;
    socklen_t clientLen = sizeof(client);
    char buffer[BUFFER_SIZE] = {0};

    // 判断程序是否异常, 异常退出
    bool flag = false;

    printf("Start to loop\n");
    while (1)
    {
        // 初始化modifyFd
        modifyFd = readFd;
        int selectReturn = select(maxfd+1, &modifyFd, NULL, NULL, NULL);
        if (selectReturn == -1)
        {
            perror("Select failed");
            break;
        }
        else if (selectReturn == 0)
        {
            printf("No event selected");
            continue;
        }

        // 循环遍历需要处理的fd
        for (int eventFd = 3; eventFd < maxfd + 1; eventFd++)
        {
            if (FD_ISSET(eventFd, &modifyFd))
            {
                if (eventFd == serverSocketFd)
                {
                    // 如果是初始套接字, 处理新连接并加入监听
                    int acceptSocketFd = 0;
                    if ((acceptSocketFd = accept(eventFd, (struct sockaddr *)&client, &clientLen)) == -1)
                    {
                        perror("Server accept connection failed");
                        break;
                    }
                    printf("Client %s:%d connected\n", inet_ntoa(client.sin_addr), ntohs(client.sin_port));
                    // 更新最大需遍历fd
                    maxfd = (acceptSocketFd > maxfd ? acceptSocketFd : maxfd);
                    // 将新的fd加入监听集合
                    FD_SET(acceptSocketFd, &readFd);
                }
                else
                {
                    // 如果是其他套接字, 读取并回显连接
                    memset(buffer, 0, sizeof(buffer));
                    memset(&client, 0, sizeof(client));
                    // 获取发送方信息
                    int getPeerReturn = getpeername(eventFd, (struct sockaddr *)&client, &clientLen);
                    if (getPeerReturn == -1)
                    {
                        perror("Get Peer name failed");
                    }
                    // 接收信息
                    int recvReturn = recv(eventFd, buffer, sizeof(buffer), 0);
                    if (recvReturn == -1)
                    {
                        printf("Receive from %s:%d failed\n", inet_ntoa(client.sin_addr), ntohs(client.sin_port));
                        perror(NULL);
                        flag = true;
                        break;
                    }
                    else if (recvReturn == 0)
                    {
                        printf("Client %s:%d disconnected\n", inet_ntoa(client.sin_addr), ntohs(client.sin_port));
                        close(eventFd);
                        FD_CLR(eventFd, &readFd);
                        continue;
                    }

                    printf("Message from client %s:%d %s\n", inet_ntoa(client.sin_addr), ntohs(client.sin_port), buffer);

                    if (!strcmp(buffer, "quit"))
                    {
                        flag = true;
                        break;
                    }

                    // 回显给发送端
                    strcat(buffer, "--Server");
                    int sendReturn = send(eventFd, buffer, strlen(buffer), 0);
                    if (sendReturn == -1)
                    {
                        printf("Send message back to %s:%d failed\n", inet_ntoa(client.sin_addr), ntohs(client.sin_port));
                        perror(NULL);
                        flag = true;
                        return -1;
                    }
                }
            }
        }

        // 判断全局异常标志, 异常退出循环, 回收资源
        if (flag)
        {
            break;
        }
    }

    for (int eventfd = 3; eventfd < maxfd + 1; eventfd++)
    {
        if (FD_ISSET(eventfd, &readFd))
        {
            close(eventfd);
        }
        
    }
    
    return 0;
}
```

## poll

- 头文件 

  #include <poll.h>

- 原型 

  int poll (struct pollfd *fds, nfds_t nfds, int timeout);

- 功能 

  同步 IO 多路复用，监视一组文件描述符，等待 fd 就绪，解决 select 的 fd 集合上限问题

- 参数 

  fds	pollfd 结构体数组，存放待监听 fd、要监听的事件、返回的就绪事件 

  nfds	数组中 pollfd 元素个数 

  timeout	超时时间，单位 ms；-1 永久阻塞；0 非阻塞立即返回；>0 等待指定毫秒

- 返回值 

  成功	返回就绪 fd 的总个数 超时返回 0 

  失败	返回 - 1（并设置错误码）

### struct pollfd

- 头文件 

  #include <poll.h>

- 原型 

  struct pollfd { 

  int fd;         /* 待监听的文件描述符 */ *

  short events;   /* 要监听的事件，输入 */ *

  short revents;  /* 内核返回的就绪事件，输出 */ 

  };

- 功能 

  poll 存放单个 fd 的监听事件与返回就绪事件

- 参数 

  fd：目标文件描述符，填负数则忽略该项 

  events：用户设置感兴趣事件，常用：POLLIN 可读、POLLOUT 可写、POLLERR 错误、POLLHUP 挂断 

  revents：内核填充，返回实际发生的事件，不需要手动设置

- 返回值 

  无，结构体成员由 poll 函数填充 revents

## epoll（一组函数，epoll_create + epoll_ctl + epoll_wait）

### epoll_create

- 头文件 

  #include <sys/epoll.h>

- 原型 

  int epoll_create (int size);

- 功能 

  创建 epoll 实例，返回 epoll 文件描述符（size 旧版本提示监听 fd 数量，现已失效）

- 参数 

  size	提示内核预期监听的文件描述符数量，现在仅作参考，不再限制上限

- 返回值 

  成功	返回 epollfd（epoll 实例的文件描述符） 

  失败	返回 - 1（并设置错误码）

### epoll_ctl

- 头文件 

  #include <sys/epoll.h>

- 原型 

  int epoll_ctl (int epfd, int op, int fd, struct epoll_event *event);

- 功能 

  向 epoll 实例注册 / 修改 / 删除待监听的文件描述符与对应事件

- 参数 

  epfd	epoll 实例描述符，epoll_create 返回值 

  op	操作类型：EPOLL_ADD 添加 fd，EPOLL_MOD 修改事件，EPOLL_DEL 删除 fd 

  fd	要操作的目标文件描述符 

  event	结构体，设置需要监听的事件（EPOLLIN 可读、EPOLLOUT 可写、EPOLLET 边沿触发等）

- 返回值 

  成功	返回 0 

  失败	返回 - 1（并设置错误码）

### epoll_wait

- 头文件 

  #include <sys/epoll.h>

- 原型 

  int epoll_wait (int epfd, struct epoll_event *events, int maxevents, int timeout);

- 功能 

  阻塞等待 epoll 实例中监听的 fd 就绪，将就绪事件拷贝到 events 数组

- 参数 

  epfd	epoll 实例描述符 

  events	输出参数，存放就绪 fd 的事件数组 

  maxevents	events 数组最大元素数量 

  timeout	超时时间，单位 ms；-1 永久阻塞；0 非阻塞；>0 等待指定毫秒

- 返回值 

  成功	返回就绪事件个数 超时返回 0 

  失败	返回 - 1（并设置错误码）

### struct epoll_event

- 头文件 

  #include <sys/epoll.h>

- 原型 

  struct epoll_event { 

  uint32_t events;    /* 监听 / 返回事件 */ *

  epoll_data_t data;  /* 用户数据联合体 */ 

  }; 

  typedef union epoll_data { 

  void *ptr; 

  int fd; 

  uint32_t u32; 

  uint64_t u64;

  } epoll_data_t;

- 功能 

  epoll 保存需要监听的事件，以及绑定的用户数据（fd / 指针等）

- 参数 

  events：事件掩码，常用 EPOLLIN 可读，EPOLLOUT 可写，EPOLLERR 错误，EPOLLHUP 挂断，EPOLLET 边沿触发，EPOLLONESHOT 单次触发 

  data：联合体，一般存放 fd；也可以自定义 ptr 携带自定义对象

- 返回值 

  epoll_ctl 时填入 events 设置监听；

  epoll_wait 返回时 events 存放就绪事件

```c
            break;
        }

    close(serverSocketFd);
    close(epoll_fd);

        }
```

```c
        {
            close(eventfd);
        }
        
    }
    
    return 0;
}
```
