# 联合体

- 定义

  ```c
  union union_name{
  	data_type1 member1;
  	data_type2 member2;
  	...
  };
  ```

- 联合体内存共享, 联合体中所有成员共享同一内存，联合体的大小取决于其最大成员的大小。内存对齐与大小计算

  ```c
  union Data {
  	int i;
  	float f;
  	char str[20];
  };
  union Data data;
  printf("Size of union: %ld\n", sizeof(data));// 输出联合体的大小
  ```

- 应用

  > 1. 节省内存: 联合体的主要用途之一是 节省内存。在需要存储不同类型的数据，但同一时刻只需要存储其中一种时，使用联合体可以极大减少内存的浪费。
  > 2. 数据类型转换: 联合体常用于 类型转换。由于联合体中的所有成员共享相同的内存，修改其中一个成员会影响其他成员。通过这种特性，可以方便地将同一块内存以不同类型的视角进行访问，这在底层编程中非常有用。
  > 3. 协议解析: 在网络编程或通信协议中，经常会需要从接收到的字节流中提取多种数据类型。在处理这些字节流时，联合体可以帮助程序员方便地将字节数组解释为特定的数据类型。
  > 4. 变长数据处理: 当需要处理变长数据时，例如某个消息可能包含不同长度的字段，联合体可以帮助动态选择处理的数据类型。例如，某个消息体可能根据不同的命令号有不同的结构，联合体可以根据命令号选择不同的数据格式。
  > 5. 与枚举结合使用: 联合体常与 枚举（enum） 一起使用，以区分联合体中当前存储的具体数据类型。通过枚举可以确定当前应该解释联合体中的哪个成员。
  > 6. 硬件寄存器访问: 在嵌入式编程中，访问硬件寄存器时，通常需要同时以不同的位段形式访问寄存器中的不同字段。联合体可以帮助方便地将寄存器的二进制位段拆解为可访问的结构

# 位域

```c
#include <stdio.h>
struct Status {
	unsigned int flag1 : 1;
	unsigned int flag2 : 1;
	unsigned int mode : 2;
	char data : 4;
};
int main() {
	struct Status s;
	s.flag1 = 1;
	s.flag2 = 0;
	s.mode= 3;// 2 bits, max value 3
	s.data= 9;// 4 bits, max value 15
	printf("Flag1: %d, Flag2: %d, Mode: %d, Data: %d\n", s.flag1, s.flag2, s.mode, s.data);
	return0;
}
```

- 限制和注意事项

  > **位域不能被取地址，位域成员不能使用指针指向它们。
  > 位域只适用于整型类型（int、unsigned int 等），位域的位数不能超过宿主类型的大小。在不同编译器下，位域的内存分配和对齐方式可能有所不同。因此位域在跨平台编程中需要谨慎使用。**

- 宿主数据类型:

位域的宿主数据类型通常是整型类型，包括 int、unsigned int、signed int，甚至一些编译器支持使用 short、long等类型。然而，不同编译器对宿主类型的处理方式可能会有所不同，存在以下特殊情况:

- 有符号和无符号类型的区别：使用 unsigned int定义位域时，值只允许是非负整数。使用 signed int或 int定义位域时，位域允许存储负数，但需要考虑符号位的影响。位域的最高位将作为符号位，表示数值的正负
  示例：

	```
	struct BitField{
		unsigned int a : 3;// 无符号位域，3位
		signed int b : 4;// 有符号位域，4位
	};

- 宿主类型的大小限制：位域的总位数不能超过宿主类型的位数。例如，对于 unsigned int，在大多数平台上是32位，因此位域定义的总位数不能超过32位。如果宿主类型为 short，通常是16位，位域的总位数不能超过16位。
  示例：

	```
	struct BitField{
		unsigned short a : 5;// 正确：位域大小不超过16位
		unsigned short b : 11;// 正确：两个位域总和不超过16位
	};
	```

- 位数超过限制: 如果试图定义位域的位数大于宿主类型（例如 unsigned int 的32位），会引发错误，因为位域不能存储超过宿主类型容量的数据。

  ```c
  struct BitField{
  	unsigned int a : 33; // 错误：超过32位的int位域
  };
  ```

- 自动分配情况: 在某些情况下，如果位域的定义使得一个宿主类型的空间无法完全容纳这些位，编译器可能会自动将位域分配到下一个可用的宿主类型。这种行为通常是由编译器处理的，它会确保各位域成员能够正确存储在结构体的内存中。

  ```c
  struct BitField{
  	unsigned int a : 16; // 16位
  	unsigned int b : 20; // 超出剩余的16位，因此会分配到下一个32位整数中
  };
  ```

- 可移植性: 不同编译器和平台对位域的存储顺序和内存对齐处理方式可能有所不同，因此，位域的可移植性存在局限性。尤其是在不同的硬件架构（如大端序和小端序）上，位域的存储顺序可能存在差异。

  > 字节序问题(大端序 vs 小端序): 在不同的平台上，位域的高位和低位的存储顺序可能会不同。例如，在小端序（little-endian）平台上，低位字节存储在低地址，而在大端序（big-endian）平台上，高位字节存储在低地址。这可能会影响位域的跨平台表现。
  >
  > 跨平台编程建议: 尽量避免依赖位域的内部实现细节，如位域成员的排列顺序和内存布局。如果必须使用位域，建议明确地处理不同平台的差异，或通过封装位操作函数来提高可移植性。

- 混合定义:位域与非位域成员在结构体中混合使用时，非位域成员会按正常对齐方式存储，而位域成员会根据宿主类型的规则进行存储。

  ```c
  struct MixedField{
  	unsigned int flag : 1; // 位域成员，占1位
  	int id; // 非位域成员，占用完整的4字节（假设int为4字节）
  	unsigned int mode : 3; // 位域成员，占3位
  };
  ```

# 枚举

- 枚举类型（enum）是 C 语言中一种用户定义的类型，允许将一组相关的整数常量定义在一起，增加代码的可读性和管理性。它通过名字定义一组整数值，以帮助程序员更加清晰地表示逻辑状态和选项。

- 定义:

  ```c
  enum Weekday {
  	Sunday, // 默认值为 0
  	Monday, // 1
  	Tuesday, // 2
  	Wednesday, // 3
  	Thursday, // 4
  	Friday, // 5
  	Saturday // 6
  };
  //enum关键字用于定义枚举, 默认情况下, 第一个标识符的值是0, 后续未赋值的标识符递增
  enum Day {
  	SUNDAY = 7,
  	MONDAY,			//8
  	TUESDAY = 10,
  	WEDNESDAY		//11
  };
  //手动未常量指定值后, 之后的常量会根据指定值继续递增
  ```

- 枚举与常量定义的比较

  - 常量定义: 可以使用#define或const定义常量，但这些常量是独立的，缺乏内在联系

    ```c
    #defineSUNDAY0
    #defineMONDAY1
    #defineTUESDAY2
    ```

  - 枚举: 一组相关的常量，集合成一个类型，具有明确的范围和递增机制

    ```c
    // 使用枚举
    enum Day {
    	SUNDAY, MONDAY, TUESDAY
    };
    ```

- C并没有严格定义枚举的底层类型, 通常会分配为int, 某些编译器中, 可以通过编译选项来指定枚举使用更小的类型, 以节省内存

# 字节对齐

## 为什么需要结构对齐

CPU访问对齐的数据比未对齐的数据快得多：
CPU 不是以字节为单位来访问内存的，而是以 “字”（word） 为单位。32位处理器，一个字通常是4字节；64位，通常是8字节。内存总线在物理设计上，一次可以传输一个完整字的数据。也就是cpu访问内存最基本的单位是字，也就是4个字节

```c
// 未对齐示例 - 性能差
struct Bad {
	char a;
	int b; // 可能从非4字节对齐地址开始
	char c;
};
// 对齐后 - 性能好
struct Good {
	int b; // 4字节对齐
	char a;
	char c;
	// 编译器自动插入padding
};
```

## 内存布局对比

- 未对齐的情况

  ```c
  struct Bad {
  	char a; // 1字节
  	int b; // 4字节 - 从地址1开始（未对齐！）
  	char c; // 1字节
  };
  
  //地址: 数据
  0x00: [a] // char a
  0x01: [b-第1字节] // int b 的第1字节
  0x02: [b-第2字节] // int b 的第2字节
  0x03: [b-第3字节] // int b 的第3字节
  0x04: [b-第4字节] // int b 的第4字节
  0x05: [c] // char c
  ```

  >CPU读取 b 的过程（32位系统）：
  >1. 第一次内存读取：读取地址 0x00-0x03 （4字节）
  >得到数据： \[a]\[b1]\[b2][b3]
  >需要：丢弃 [a] ，保留 \[b1]\[b2][b3]
  >2. 第二次内存读取：读取地址 0x04-0x07 （4字节）
  >得到数据： \[b4]\[c]\[pad]\[pad]
  >需要：只取 [b4] ，丢弃其他
  >3. 数据拼接：在CPU内部将 \[b1]\[b2]\[b3] 和 [b4] 组合成完整的int
  >总共：2次内存访问 + 数据屏蔽和拼接操作

- 对齐的情况

  ```c
  struct Bad {
  	char a; // 1字节 //编译器自动添加3字节padding
  	int b; // 4字节 - 从地址4开始
  	char c; // 1字节 //编译器自动添加3字节padding
  };
  //一共是12个字节！！！
  //优化：占字节数小的成员挨着放，既满足字节对齐还节省内存
  struct Good {
  	int b; // 4字节 - 从地址0开始（完美对齐）
  	char a; // 1字节
  	char c; // 1字节
  	// 编译器自动添加2字节padding
  };
  
  //地址: 数据
  0x00: [b-第1字节] // int b 的第1字节
  0x01: [b-第2字节] // int b 的第2字节
  0x02: [b-第3字节] // int b 的第3字节
  0x03: [b-第4字节] // int b 的第4字节
  0x04: [a] // char a
  0x05: [c] // char c
  0x06: [padding] // 填充
  0x07: [padding] // 填充
  ```

  >CPU读取 b 的过程（32位系统）：
  >1. 单次内存读取：读取地址 0x00-0x03 （4字节）
  >直接得到完整的int值： \[b1]\[b2]\[b3][b4]
  >无需任何数据操作，直接使用
  >总共：1次内存访问，无额外操作，用少量内存空间换取显著的性能提升！

- 总结

  > ​        字节对齐的本质是想cpu访问数据的时候，能访问一次就访问一次，占字节数比较大的成员也尽量次数少，浪费了一些空间，但提高了访问效率！！！
  >
  > ​        所以，结构体字节对齐的本质是 编译器在编译期间通过插入“填充字节”（Padding）来优化内存布局，以确保程序在运行时，CPU 能够以最少的次数、最高效的方式访问内存中的数据。
  >
  > ​        这是一种 “以空间换时间” 的经典权衡：牺牲少量的内存空间（填充字节），换取程序运行速度的显著提升和稳定性的保证。对于现代CPU来说，内存非常廉价，而CPU周期极其宝贵，这个交换是非常值得的。

## 结构体字节对齐核心原则

- 成员自身对齐

  > 每个成员的起始地址必须是其自身大小与编译器指定对齐值（可通过 **#pragma pack()** 修改）两者中较小者的整数倍
  >
  > 也就是如果是64位系统，编译器默认的对齐值是8字节，如果最大字节数的成员小于8字节，那就按照最大的这个成员的字节数对齐

![image-20260819140513899](/assets/pictures/结构体对齐1.png)

- 结构体整体对齐(最终大小规则)

  > 结构体的最终总大小必须是其所有成员中最大对齐单位与编译器指定对齐值（ pack 值）两者中较小者的整数倍。编译器可能会在末尾添加填充字节以满足此要求

- 系统默认对齐

  当没有使用 #pragma pack 指定时，编译器的默认对齐方式通常如下：

  > 32位系统：默认最大对齐单位为 4字节。即使有 long long （8字节）成员，通常也按4字节对齐（但其自身的8字节对齐要求仍需在结构体内部满足，见原则一）。
  > 64位系统：默认最大对齐单位通常为 8字节。能更好地支持 double 和 long long 等8字节类型。

- 可定制对齐

  > 使用预处理指令 **#pragma pack(n)** 可以显式指定对齐值（ n 通常为 1, 2, 4, 8, 16）。
  > **#pragma pack(1) **：实现紧凑布局，无填充，但可能降低访问效率（尤其是非对齐内存访问代价
  > 高的平台）。
  > **#pragma pack() **：恢复默认对齐

## 经典示例

```c
// 假设：64位系统，默认8字节对齐，无pack
struct Example {
    char a; // 大小1，偏移0
    // 填充3字节（使int起始地址为4的倍数）
    int b; // 大小4，偏移4
    short c; // 大小2，偏移8
    double d; // 大小8，偏移16 (必须是8的倍数)
    // 结构体总大小暂时为24
    // 整体对齐：最大对齐单位是8，24 % 8 == 0，无需末尾填充
}; // sizeof(Example) = 24
// 使用 #pragma pack(2)
#pragma pack(push, 2)
struct PackedExample {
    char a; // 偏移0
    // 填充1字节（使int起始地址为min(4,2)=2的倍数）
    int b; // 偏移2
    short c; // 偏移6
    double d; // 偏移8 (必须是min(8,2)=2的倍数)
    // 总大小16
    // 整体对齐：16 % 2 == 0
}; // sizeof(PackedExample) = 16
#pragma pack(pop)
```

- 定义一个Book结构体,包含书名, 作者, 价格, 出版年份等信息, 输入3本书并按价格升序输出

  #include <stdlib.h>
  #include <stdbool.h>
  #include <string.h>
  
  typedef struct{
      char bookName[20];
      char author[20];
      float price;
      int year;
  }bookBook;
  
  void copybook(bookBook *book1, bookBook *book2){
      strcpy(book1->author, book2->author);
      strcpy(book1->bookName, book2->bookName);
      book1->price = book2->price;
      book1->year = book2->year;
  }
  
  void switchbook(bookBook *book1, bookBook *book2){
      bookBook temp;
      copybook(&temp, book1);
      copybook(book1, book2);
      copybook(book2, &temp);
  }
  
  int main(int argc, char *argv[])
  {
      bookBook book[3];
      for(int i = 0; i < 3; i++){
          scanf("%s %s %f %d", book[i].bookName, book[i].author, &book[i].price, &book[i].year);
      }
      if(book[0].price > book[1].price){
          switchbook(&book[0], &book[1]);
      }
      if(book[1].price > book[2].price){
          switchbook(&book[1], &book[2]);
      }
      if(book[0].price > book[1].price){
          switchbook(&book[0], &book[1]);
      }
      for(int i = 0; i < 3; i++){
          printf("%s %s %f %d\n", book[i].bookName, book[i].author, book[i].price, book[i].year);
      }
      return 0;
  }

#include <stdbool.h>
#include <string.h>

typedef enum{
    RED,
    YELLOW,
    GREEN
}LightState;

int main(int argc, char *argv[])
{
    LightState currentLight = RED;
    int i = 7;

        switch(currentLight){
            case RED:
                printf("当前灯为：RED\n");
                currentLight = (currentLight + 1) % 3;

                break;

# 错误分析

- 位域的主要作用是控制结构体和成员大小

- 结构体和联合体的区别:

  > 1. 结构体 (struct) 是一种聚合数据结构，它能够将不同类型的数据组合在一起，每个成员都有独立的内存空间。
  > 2. 联合体 (union) 也是一种聚合数据结构，它与结构体类似，但联合体的所有成员共享同一块内存空间，即所有成员共用同一内存地址，只有一个成员能够在任何时刻存储值。
  > 3. 结构体适用于需要同时存储多个不同数据类型的情况，而联合体适用于在同一内存空间中存储不同类型的数据，但一次只能使用其中一个成员。

- 联合体的内存管理方式及其优缺点

  > 1. 联合体内存管理的特点是所有成员共享同一块内存空间。内存大小等于最大成员的大小，成员的变化会影响整个联合体。
  > 2. 联合体节省内存，但每次只能存储其中一个成员的数据，适用于存储互斥的数据。
