# UART串口控制器笔记

## 1 串口通信协议基础

### 1.1 什么是 UART 串口通信

UART（通用异步收发器），**串行通信：数据一位一位依次传输**，不需要同步时钟信号线。 硬件最少三根线完成通信：`TX`（发送）、`RX`（接收）、`GND`（共地）。

> 接线规则：**交叉连接**，A 设备 TX 接 B 设备 RX；A 设备 RX 接 B 设备 RX；GND 互相直连。 ⚠️GND 必须共地，否则电平参考不一致，通信乱码。

### 1.2 波特率

- 波特率：一秒钟传输码元的个数；UART 异步串口下，波特率 = 比特率。
- 常用波特率：`2400、4800、9600、115200`。
- STM3F4 波特率计算公式 \(Baud\ rate=\frac{f_{CK}}{8*(2‑OVER8)*USARTDIV}\)
- `fck`：串口外设时钟；APB1 最大 42MHz，APB2 最大 84MHz
- `OVER8`：过采样模式；`OVER8=0`为 16 倍过采样，`OVER8=1`为 8 倍过采样
- `USARTDIV`：波特率分频值，分为`DIV_Mantissa`（整数部分）、`DIV_Fraction`（小数部分）

> 通信双方波特率、帧格式必须完全一致，否则接收乱码。

### 1.3 UART 一帧完整帧格式

帧顺序：**起始位 → 数据位 → 校验位（可选） → 停止位**

1. **起始位**：固定低电平，通知接收方一帧数据开始

2. **数据位**：可配置 8bit /9bit，低位优先（LSB 先发送），最常用 8 位

3. 校验位（可选）

   - 偶校验：帧内数据 bit 中 1 的总个数为偶数
   - 奇校验：帧内数据 bit 中 1 的总个数为奇数

   > 开启校验位时，如果配置 8 位数据位，实际有效数据只有 7bit，1bit 用作校验。

4. **停止位**：固定高电平；支持 0.5、1、1.5、2 位停止位；最常用**1 位停止位**。

> 标准常用配置简写：`9600‑8‑N‑1` 含义：波特率 9600，8 数据位，无校验，1 停止位。

## 2 UART 收发流程与状态标志、中断

### 2.1 发送流程

1. CPU 把待发送数据写入`TDR`发送数据寄存器
2. 硬件自动将 TDR 数据送入**发送移位寄存器**
3. 移位寄存器逐比特移位，从 TX 引脚输出串行波形

### 2.2 接收流程

1. RX 引脚检测到起始位下降沿，启动接收
2. 串行比特进入**接收移位寄存器**
3. 接收完成后，把并行字节存入`RDR`接收数据寄存器
4. CPU 读取 RDR，把数据读到内存。

### 2.3 核心状态标志位（SR 寄存器）

表格

| 标志位 | 名称               | 含义                                            |
| ------ | ------------------ | ----------------------------------------------- |
| TXE    | 发送数据寄存器为空 | TDR 寄存器已经空，可以写入下一个待发字节        |
| TC     | 发送移位寄存器为空 | 全部数据已经移位发送完成，TX 线路回到空闲高电平 |
| RXNE   | 接收数据寄存器非空 | RDR 收到新数据，可以读取                        |
| IDLE   | 线路空闲           | 检测到 RX 长时间高电平，线路空闲                |
| ORE    | 接收溢出错误       | RDR 数据还没被 CPU 读走，又收到新字节，数据丢失 |
| PE     | 奇偶校验错误       | 开启校验时，收到数据校验不匹配                  |

### 2.4 UART 中断

状态标志配合使能位，可以产生串口中断送给 NVIC。

表格

| 中断事件         | 标志位 | 中断使能位 | 触发说明                       |
| ---------------- | ------ | ---------- | ------------------------------ |
| 发送寄存器空中断 | TXE    | TXEIE      | TDR 为空，可以继续发送下一字节 |
| 发送完成中断     | TC     | TCIE       | 整帧全部发送完毕               |
| 接收就绪中断     | RXNE   | RXNEIE     | 收到 1 字节新数据              |
| 奇偶校验错误中断 | PE     | PEIE       | 校验出错                       |
| 线路空闲中断     | IDLE   | IDLEIE     | 检测到总线空闲                 |

### 2.5 DMA 搬运

UART 可以配合 DMA，实现**CPU 零参与数据收发**：

1. DMA 发送：TXE 置 1，DMA 自动把内存数据搬运到 TDR 寄存器
2. DMA 接收：RXNE 置 1，DMA 自动把 RDR 的数据搬运到内存数组。

## 2.6 硬件流控 RTS / CTS

用于高速通信，防止接收方处理不过来造成丢包，额外 2 根硬件信号线。

- **nRTS（输出）**：本设备输出，告诉对方：我是否可以接收数据。低电平 = 准备就绪。
- **nCTS（输入）**：本设备输入，读取对方状态；只有 nCTS 为低电平，才允许发送下一组数据。

工作逻辑：

1. RTSE=1（开启 RTS）：接收缓冲区有空，nRTS 拉低；接收满，nRTS 拉高，通知发送方暂停。
2. CTSE=1（开启 CTS）：发送发送前检查 nCTS 引脚；nCTS 有效 (低) 才发送；无效则暂停发送，当前已经在发送的帧会发送完成后停止。

> 普通传感器、调试串口一般**不开启硬件流控**。

## 4 HAL 库 UART 接口

### 4.1 UART 初始化结构体

```
typedef struct {
uint32_t BaudRate;        //波特率
uint32_t WordLength;       //数据位长度
uint32_t StopBits;         //停止位
uint32_t Parity;           //奇偶校验
uint32_t Mode;              //收发模式，TX/RX/TX_RX
uint32_t HwFlowCtl;         //硬件流控 RTS/CTS/NONE
} UART_InitTypeDef;
```

### 4.2 核心 API 函数汇总

表格

| 函数原型                                                     | 功能说明                   |
| ------------------------------------------------------------ | -------------------------- |
| `HAL_StatusTypeDef HAL_UART_Init(UART_HandleTypeDef *huart)` | 初始化串口控制器寄存器     |
| `HAL_StatusTypeDef HAL_UART_Transmit(UART_HandleTypeDef *huart,const uint8_t *pData,uint16_t Size,uint32_t Timeout)` | 轮询（阻塞）发送，超时退出 |
| `HAL_StatusTypeDef HAL_UART_Receive(UART_HandleTypeDef *huart,uint8_t *pData,uint16_t Size,uint32_t Timeout)` | 轮询（阻塞）接收，超时退出 |
| `HAL_StatusTypeDef HAL_UART_Transmit_IT(UART_HandleTypeDef *huart,const uint8_t *pData,uint16_t Size)` | 中断方式发送               |
| `HAL_StatusTypeDef HAL_UART_Receive_IT(UART_HandleTypeDef *huart,uint8_t *pData,uint16_t Size)` | 中断方式接收               |
| `HAL_StatusTypeDef HAL_UART_Transmit_DMA(UART_HandleTypeDef *huart,const uint8_t *pData,uint16_t Size)` | DMA 模式发送               |
| `HAL_StatusTypeDef HAL_UART_Receive_DMA(UART_HandleTypeDef *huart,uint8_t *pData,uint16_t Size)` | DMA 模式接收               |

> `HAL_MAX_DELAY`：无限超时；阻塞轮询 API 在大数据、高速场景容易卡死。

## 5 电平标准（TTL / USB‑UART / RS232 / RS485）

### 5.1 TTL 电平（STM32 芯片引脚输出）

- 逻辑`0`：0 ~ 0.4V
- 逻辑`1`：2.4V ~ 3.3V /5V

> STM32 IO 输出为 TTL 电平，不能直接接 RS232 设备。

### 5.2 USB‑UART（USB 转 TTL）

PC 没有 TTL 串口，需要**CH340/CP2102**芯片，实现 USB ↔ TTL 电平转换。 接线：芯片 TX 接 STM32‑RX；芯片 RX 接 STM32‑TX；GND 共地。

### 5.3 RS232 电平（远距离，MAX232 芯片转换）

- TTL 逻辑 1 → RS232 输出 **‑3V ~ ‑15V**
- TTL 逻辑 0 → RS232 输出 **+3V ~ +15V**

> 需要 MAX232 电平转换芯片；物理接口常为 DB9 母头；抗干扰能力强，传输距离远。

### 5.4 RS485 差分电平

使用 A、B 两根差分信号线，依靠压差判断逻辑：

- 逻辑 1：`VA‑VB = +2V ~ +6V`
- 逻辑 0：`VA‑VB = ‑2V ~ ‑6V` 抗干扰能力最强，工业远距离总线；芯片如 MAX485。常用于 Modbus‑RTU 协议。

## 6 UART 应用案例

### 案例 1：GP2Y1026AU0F 粉尘传感器（你工程使用）

1. 串口参数：**2400‑8‑N‑1**

2. 帧格式（7 字节）

   表格

   | 字节 0    | 字节 1 | 字节 2 | 字节 3 | 字节 4 | 字节 5 | 字节 6    |
   | --------- | ------ | ------ | ------ | ------ | ------ | --------- |
   | 0xAA 帧头 | Vout_H | Vout_L | Vref_H | Vref_L | 校验和 | 0xFF 帧尾 |

校验规则：`checksum = data[1]+data[2]+data[3]+data[4]`

换算公式（讲义版本） \(Vout=\frac{Vout(H)*256+Vout(L)}{1024} * 5\) \(浓度(\mu g/m^3)=3300 * Vout\)

> ⚠️注意：教学模拟器与真实传感器载荷语义不同；模拟器直接把 data1、data2 当做浓度；实物是 ADC 电压码。 帧头、帧尾、校验通过，只能代表**二进制字节收发一致，不能代表解析语义一致**。

### 案例 2：Modbus‑RTU 土壤温湿度传感器

1. 参数：4800‑8‑N‑1，设备默认地址`0x01`
2. 主从问答机制：主机发送请求帧，从机回复响应帧。
3. 负数使用**补码格式**传输； 示例：`0xFF9F`代表‑97，实际温度 =‑9.7℃； 湿度`0x01E6 =486` →湿度 48.6%。

## 7 常见坑总结（写入笔记）

1. 通信双方**波特率、数据位、停止位、校验位必须完全一致，否则乱码**。
2. TTL 通信必须共 GND；缺少共地会随机乱码。
3. 阻塞`HAL_UART_Receive`配合`HAL_MAX_DELAY`，一旦帧错位程序永久卡死；工程优先中断 / DMA。
4. 校验和只能校验字节传输错误，**不能校验上层协议语义**。
5. 电平标准不能直接混接：TTL 不能直连 RS232，必须电平转换芯片。
6. GP2Y1026AU0F 实物波特率是 2400，模拟器很多是 9600，调试实物需要修改 CubeMX 串口配置。
