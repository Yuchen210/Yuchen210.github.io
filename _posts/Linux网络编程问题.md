1  什么是网络体系结构？网络体系结构的分类？

为完成计算机之间的通信, 把网络的功能分层定义, 规定各层的服务, 接口, 协议的一套完整的规范, 核心思想是分层思想

主要分为OSI七层和TCP/IP4层, 实际上主要使用的是TCP/IP模型

2  OSI体系结构分成几层？分别是什么？

OSI体系结构分为7层, 从上至下依次为: 应用层, 表示层, 会话层, 传输层, 网络层, 数据链路层, 物理层

3 TCP/IP体系结构分成几层？分别是什么？说说各层常见的协议？

TCP/IP结构分为4层, 从上至下依次为: 应用层, 传输层, 网络层, 网络接口与物理层

4  什么是IP地址？ipv4和ipv6的区别？

IP地址是互联网中主机/网络设备的逻辑编号, 用来在网络层标识一台设备, 实现跨网络寻址\路由转发

| 对比维度 | IPv4       | IPv6         |
| -------- | ---------- | ------------ |
| 地址长度 | 32位       | 128位        |
| 表示方式 | 点分十进制 | 冒分16进制   |
| IP首部   | 可变长度   | 固定40字节   |
| 分片     | 可分片     | 仅源主机分片 |

6 端口号的作用是什么？

16位整数, 0-65535, 与IP地址共同组成套接字, 唯一标识通信端点, 通过不同端口号访问不同服务

7  什么是主机字节序？什么是网络字节序？

网络字节序: 大端序, 高位字节在前, 如0x1234存储为12 34, 高位低地址

主机字节序: 小端序, 高位字节在后, 如0x1234存储位34 12, 高位高地址

10  “TCP”为什么是可靠连接？

TCP协议面向连接,  传输过程中会有丢包重传机制, 发送方如果未收到接收方的ack报文, 会认为数据丢失然后超时重发, 因此被称为可靠连接

11  说说三次握手和四次挥手的过程？

- 三次握手: 客户端发送给服务端SYN报文, 进入SYN_SENT状态, 服务端在收到报文后发送SYN+ACK报文, 进入SYN_RCVD, 客户端在收到服务端报文后, 发送ACK报文, 进入ESTABLISHED, 服务端在接收到ACK报文后同步进入ESTABLISHED
- 四次挥手: A发起FIN报文然后进入FIN_WAIT_1状态, B在收到A的FIN报文后回复ACK,继续发送剩余数据 然后进入CLOSE_WAIT状态, A收到ACK后进入FIN_WAIT_2状态, B发送完数据后发送FIN报文, 然后进入LAST_ACK状态, A在收到FIN报文后回复ACK报文, 然后进入TIME_WAIT状态, 定时器到达后关闭连接, B在收到ACK报文后直接关闭连接

13  “TCP”“UDP”的区别？

| 对比项   | TCP                                                          | UDP                                                        |
| -------- | ------------------------------------------------------------ | ---------------------------------------------------------- |
| 连接特性 | **面向连接**，通信前三次握手建立连接，结束四次挥手释放连接   | **无连接**，不用建立连接，直接发包                         |
| 可靠性   | 可靠传输。确认应答、超时重传、流量控制、拥塞控制，数据无丢失、无重复、按序到达 | 不可靠。不确认、不重传，丢包不会重发；不保证顺序           |
| 报文形式 | 字节流，没有报文边界，是连续的字节流                         | 数据报，有报文边界，一次发送一个完整 UDP 报文              |
| 首部开销 | 首部 20~60 字节（固定 20 字节 + 选项）                       | 首部固定 8 字节，开销很小                                  |
| 控制机制 | 有：确认应答、超时重传、滑动窗口（流量控制）、拥塞控制       | 无流量、拥塞、重传机制                                     |
| 适用场景 | 文件传输、网页浏览、邮件、数据库（要求准确）：HTTP/HTTPS、FTP、SSH | 直播、视频通话、DNS 查询、游戏（能接受少量丢包，追求速度） |

19 TCP有没有丢包处理？通过什么方法处理丢包？

有丢包处理, 核心依靠超时重传,辅以快速重传

 发送方发送报文后, 启动超时计时器, 如果超时还没收到ACK, 判断报文丢失, 重传该报文, 如果接收方收到失序报文, 立刻发送重复ACK, 如果发送方收到3个重复ACK, 立刻重传

20 为什么三次握手的客户端还需要发送一次确认包？

服务端需要知道客户端已经成功接收到消息并建立了连接, 然后才会建立连接, 如果收不到客户端的确认, 并不会创建资源

21  Linux系统中有几种IO模型？分别是什么？

阻塞IO, 非阻塞IO, IO多路复用, 信号驱动IO, 异步IO

22  网络通信中阻塞和非阻塞的区别？

阻塞是指程序在等待读写的时候, 如果没有就绪, 程序会进入休眠, 等待就绪的发生, 不会执行其他操作

非阻塞是指程序在等待读写的时候, 如果没有就绪, 程序不会等待, 而是继续执行其他操作

23  网络服务器模型有几种？分别是什么？

多进程模型	为每一个连接创建一个进程

多线程模型	为每一个连接创建一个子线程

IO多路复用模型	单个文件监听所有连接, 搭配线程池处理多个请求

24  网络服务器超时检测的方法有哪些？

应用层心跳包	客户端定时发送心跳，服务端记录最后收到心跳的时间，超时未收到则关闭连接，业务可控，长连接常用。

TCP自带keepalive	TCP 内核保活机制，内核定时发送探测报文，多次无应答判定连接失效，无需业务发包；仅检测 TCP 层连接

读写超时	设置 recv/send 调用的阻塞超时，多用于阻塞 IO，epoll 多路复用场景效果差

25  什么是广播？广播地址一般是什么？

向同一个网段内所有主机发送数据包, 一台发, 网段内所有主机都会收到这个报文

广播地址: 网络位不变, 主机位全部置1, 如192.168.1.0/24 广播地址为192.168.1.255

26  什么是组播？组播地址范围？

一对多通信, 数据包发送给一组加入该组播的主机, 而不是全网的所有主机, 只有加入了组播的主机才会收到该报文

IPv4广播地址224.0.0.0~239.255.255.255

27  什么是UNIX域套接字？

UNIX域套接字是linux下本机进程间通信IPC方式, 地址组AF_UNIX, 使用文件路径作为通信地址, 绕过TCP/IP协议栈, 数据在内核内存直接拷贝, 不存在丢包

29  什么是数据库？什么是嵌入式数据库？常见的嵌入式数据库有哪些？

按照一定结构组织, 存储和管理数据的集合, 提供增删改查, 事务, 索引等能力

嵌入式数据库不需要单独启动数据库服务器, 数据库引擎作为程序库嵌入到应用进程, 直接调用API读写本地文件

最常见SQlite

30 什么是SQLite?它的主要特点是什么？

零配置, 无后台进程, 但数据库文件, C语言实现, 体积小, 支持标准SQL+ACID事务, API简单, 开启WAL预写日志模式后, 读写可以并发, 短板是同一时刻只能由一个写事务

31SQLite和MySQL有什么区别？

| 对比项   | SQLite                                                     | MySQL                                                        |
| -------- | ---------------------------------------------------------- | ------------------------------------------------------------ |
| 架构     | 嵌入式，库文件链接进应用，**同进程**，无独立服务           | 客户端 / 服务端 C/S 架构，独立 mysqld 后台进程，客户端通过 TCP/UDS 连接访问 |
| 进程模型 | 一个进程内使用；多进程访问靠文件锁                         | 支持多客户端、多进程、多线程并发访问                         |
| 存储形式 | **单个 db 文件**，整张数据库就是一个文件                   | 多个文件，表空间、日志、配置分开管理                         |
| 网络访问 | **不支持网络访问**，只能本机进程调用库 API                 | 支持 TCP 网络连接，可以跨主机远程访问                        |
| 部署运维 | 零配置，不用启动服务、无账号密码，开箱即用                 | 需要安装、启动服务，管理账号、权限、端口，需要运维           |
| 并发能力 | WAL 模式：**多读，单写**；同一时刻只能 1 个写事务，写串行  | 支持多读写并发，锁粒度更细（行锁 InnoDB），支持大量并发连接  |
| 资源占用 | 非常轻量，内存 CPU 占用小，适合嵌入式网关                  | 资源开销大，需要持续占用内存，不适合资源受限嵌入式设备       |
| 事务     | 支持 ACID 事务，崩溃恢复（WAL）                            | InnoDB 引擎完整 ACID，事务能力更强                           |
| 适用场景 | 嵌入式设备、网关、单机本地持久化、移动端本地存储、小数据量 | Web 后端、多客户端服务、大量并发读写、跨机器访问             |

32 SQLite适用于哪些场景？不适合哪些场景？

SQlite适合嵌入式设备, 单机本地持久化, 小数据量, 不适合多客户端大量并发写入, 超大分布式集群, 远程多机器共享数据库

34  数据库和文件的区别？

普通文件: 原始字节流, 没有内置数据结构, 索引, 事务, 读写全靠应用自己解析

数据库: 一套带存储引擎的软件, 底层依然操作文件, 但封装了索引, sql查询, 事务, 锁, 并发, 数据类型等

35 为什么TIME_WAIT状态需要等待2MSL？

需要等待确认对方收到了自己发送的ACK报文, 如果对方未收到报文, 会一直处于close_wait状态, 无法释放资源. 等待2MSL, 如果对方没收到ACK报文, 会重发SYN报文, 此时就可以再次回复, 确保连接关闭

36 TCP的粘包问题是什么？如何解决？

TCP本身是面向字节流的, 发送端本身可能会减少发送次数而将多个包合并成一个发送, 数据包无法区分边界, 接收端在读取时无法分隔数据包

定长发送, 特殊字符分隔, 封装消息长度

37 什么是NAT(网络地址转换)？

将内网私有IP地址转换成公网IP, 实现多台内网设备公用一个公网IP上网, NAT服务器会将内网的IP和端口转换成公网的IP和端口, 并维护一个转换表, 当公网IP到达时, 查表将对应数据转发给内网私有IP
