# 第1章 C++ 基础语法

## 1-1 标识符

**定义**：标识符是用于命名变量、函数、类、对象等实体的名称。C++ 中几乎所有用户定义的元素都需要一个唯一标识符。

**构成规则**

- 只能由 `数字(0~9)`、`大写字母(A~Z)`、`小写字母(a~z)`、`下划线(_)` 组成
- 不能以数字开头
- 不能是关键字
- 不能包含特殊字符（`# $ & @` 等）
- **严格区分大小写**（`Value` 与 `value` 是两个不同标识符）

```cpp
int myfor = 10;      // 正确：不是关键字，只是名字里带 for
int for = 10;        // 错误：for 是关键字
int 2value = 10;     // 错误：数字开头
int value$name = 10; // 错误：特殊字符
int Value = 1;       // 正确
int value = 2;       // 正确，与 Value 不同
```

**命名风格**

| 风格             | 规则                             | 示例                                |
| ---------------- | -------------------------------- | ----------------------------------- |
| 大驼峰（Pascal） | 每个单词首字母大写               | `LastName` `FirstName`              |
| 小驼峰（Camel）  | 首个单词小写，后续单词首字母大写 | `lastName` `firstName`              |
| 下划线（Snake）  | 单词之间用 `_` 连接              | `set_value` `get_value` `_hal_init` |

> 工程实践：变量小驼峰、函数小驼峰、类名大驼峰、宏全大写；同一工程内**风格必须统一**。
> 「见名知意」优先：`int a` 不如 `int studentAge`。

## 1-2 关键字

**定义**：由编程语言本身定义的、具有特殊含义的保留字，用于声明变量、控制流程、定义类型等。

- 不能用作变量名、函数名等自定义标识符
- 全部小写，区分大小写
- C++98/03 共 63 个关键字，其中与 C 语言一致的 33 个

常见关键字分组记忆：

| 分类       | 关键字                                                       |
| ---------- | ------------------------------------------------------------ |
| 类型       | `bool char int float double void wchar_t short long signed unsigned auto` |
| 流程       | `if else switch case default for while do break continue goto return` |
| 类与对象   | `class struct union enum public private protected this friend virtual operator namespace using template typename explicit mutable` |
| 常量与存储 | `const static extern register volatile`                      |
| 内存管理   | `new delete sizeof`                                          |
| 异常       | `try catch throw`                                            |
| 转换       | `static_cast dynamic_cast const_cast reinterpret_cast`       |
| 布尔/其他  | `true false inline typeid asm typedef export`                |

> 注意：`auto` 在 C++11 中被重用为类型推导，语义与 C 语言完全不同（考点）。

## 1-3 标准输入输出流

**什么是流**：一种抽象的数据传输方式，允许数据按顺序从一个地方流向另一个地方。C++ 把输入输出过程称为「流(stream)」，做输入输出的类统称为「流类」。

| 对象   | 所属类    | 作用               | 运算符    |
| ------ | --------- | ------------------ | --------- |
| `cin`  | `istream` | 标准输入（键盘）   | 提取 `>>` |
| `cout` | `ostream` | 标准输出（显示器） | 插入 `<<` |
| `cerr` | `ostream` | 标准错误，不带缓冲 | `<<`      |
| `clog` | `ostream` | 标准错误，带缓冲   | `<<`      |

使用前必须包含头文件：

```cpp
#include <iostream>
using namespace std;   // 或 std::cout / std::cin

int main()
{
    int age;
    cin >> age;                      // 键盘输入
    cout << "age = " << age << endl; // 输出
    return 0;
}
```

**endl 与 "\n" 的区别（高频考点）**

| 写法   | 换行 | 刷新缓冲区             |
| ------ | ---- | ---------------------- |
| `endl` | 是   | **是**（会调用 flush） |
| `"\n"` | 是   | 否                     |

> 结论：频繁输出时用 `"\n"` 更快；需要立即看到输出（如调试、日志、崩溃前）用 `endl`。

**格式化控制**（需要 `<iomanip>`）

```cpp
#include <iomanip>
cout << setw(8) << setfill('0') << 42 << endl;   // 00000042
cout << fixed << setprecision(2) << 3.14159;     // 3.14
cout << hex << 255 << dec << endl;               // ff
```

## 1-4 程序注释

**作用**：嵌入代码中的解释性文本，提高可读性与可维护性；不参与编译执行。

```cpp
// 单行注释：从 // 到行末

/*
 * 多行注释：从 /* 开始，到 */ 结束
 */
int a = 20; // 这是单行注释
```

**三个必须知道的坑**

1. **不支持嵌套多行注释**

```cpp
/*  这是错误的
/*  内层注释  */
*/
```

正确做法：外层用多行，内层用单行。

```cpp
/*
// 内层用单行注释，可以
*/
```

2. **条件编译注释**：批量注释代码推荐 `#if 0 ... #endif`，不受 `*/` 干扰，可嵌套

```cpp
#if 0
int a = 20;
a = 10;
#endif
```

3. `//` 后面的内容在**字符串里不生效**，注意 URL 里的 `//`（`"http://..."` 是字符串，不是注释）。

## 1-5 代码风格

**定义**：一组约定和规则，规定如何写出清晰、一致、易维护的代码，包括命名、缩进、注释、代码结构等。

**为什么重要**

- 代码更整洁一致
- 可读性更高，逻辑更清晰
- 便于调试、修复、团队协作

**常用约定**

- 缩进统一用 Tab 或 4 个空格（一个工程只用一种）
- 函数参数过多时换行缩进对齐
- 逻辑块之间适当加空行
- 函数名见名之意（动词开头：`getAge`、`setValue`、`isReady`）
- 关键逻辑、边界条件、魔数要加注释

# 第2章 命名空间

## 2-1 命名空间简介

**定义**：一种组织代码的语言特性，使标识符可以在不同上下文中使用相同名字而不冲突。

**为什么需要**

1. **防止命名冲突**：大型项目或多库集成时，不同模块可能定义了同名标识符
2. **划分逻辑单元**：按功能/模块组织代码，便于管理协作
3. **提高可读性与可维护性**：结构清晰

C++ 通过关键字 `namespace` 定义命名空间。

## 2-2 定义与使用命名空间

**语法**

```cpp
namespace 命名空间名 {
    // 声明/定义 变量、函数、类……
}
```

**示例**

```cpp
namespace myspace1 {
    int a;
    int add_int(int a, int b);
}

namespace myspace2 {
    int a = 10;
    int add_int(int a, int b) { return a + b; }
}
```

**访问方式：作用域解析运算符 `::`**

```cpp
myspace1::a = 1;
myspace2::a = 20;
int sum = myspace2::add_int(3, 4);
```

> 好处：明确指定访问哪个命名空间的成员，代码清晰，减少冲突。

## 2-3 using 关键字

`using` 是一种「语法糖」，用于简化代码、提高可读性：引入整个命名空间或其中特定成员，避免每次写 `::`。

**引入整个命名空间**

```cpp
using namespace std;
```

**引入特定成员（推荐）**

```cpp
using std::cout;
using std::endl;
```

**注意事项（重点）**

- `using namespace` 整个引入容易造成名称冲突，**建议只在局部作用域（函数内）或只引入特定成员**
- 过度使用会让不熟悉简写的开发者难以理解代码

> 工程规范：头文件里**禁止** `using namespace`（会污染所有包含它的文件）；源文件中可局部使用。

## 2-4 匿名命名空间

**定义**：`namespace` 后不跟名字，即匿名命名空间。

```cpp
namespace {
    int helper = 0;
    void internalFunc() { }
}
```

**核心作用**：匿名命名空间内的内容**不能跨文件访问**，仅限声明它的文件内可见 —— 等价于 C 语言里的 `static`（内部链接），是替代 `static` 的现代写法。

**访问方式**：同一源文件内直接访问；若有名称冲突，可用 `::成员` 显式指定匿名命名空间中的成员。

```cpp
namespace {
    int value = 10;
}
int value = 20;              // 全局同名

void f()
{
    int x = value;           // 有歧义，需显式区分
    int y = ::value;         // 明确访问匿名命名空间里的
}
```

## 2-5 嵌套命名空间与别名

**语法**

```cpp
namespace myspace1 {
    namespace myspace2 {
        void function() {}
    }
}
```

C++17 起可简写 `namespace myspace1::myspace2 { ... }`。

**访问**

```cpp
myspace1::myspace2::function();
```

**命名空间别名**（层级太深时简化）

```cpp
namespace my = myspace1::myspace2;
my::function();
```

**好处**：避免冲突、结构清晰、便于模块化设计。

# 第3章 基本数据类型（bool / string）

## 3-1 布尔类型 bool

**定义**：表示逻辑值的数据类型，名字来源于数学家 George Boole，是条件判断和逻辑运算的核心。

**内存占用**：逻辑上只需 1 bit，但实际实现中 `bool` 通常占 **1 字节**（寻址最小单位是字节）。

**核心特性**

- C++ 中 `bool` 是**基本数据类型**（C 语言是 `_Bool` + `<stdbool.h>` 的宏）
- 允许任何数据类型**隐式转换**为 `bool`：非零为 `true`，零为 `false`
- 字面量：`true` / `false`

```cpp
bool flag = true;
bool b1 = 0;      // false
bool b2 = -5;     // true（非零即真）
bool b3 = 0.0;    // false
bool b4 = "abc";  // true（指针非空）

int x = flag;     // 1
double d = false; // 0.0
```

**打印格式控制**

```cpp
bool v = true;
cout << v << endl;                        // 1
cout << boolalpha << v << endl;           // true
cout << noboolalpha << v << endl;         // 恢复 1
```

**C 与 C++ 对比（考点）**

| 特性       | C 语言（C99+）                    | C++                   |
| ---------- | --------------------------------- | --------------------- |
| 是否内置   | `_Bool` 是内置类型（`bool` 为宏） | `bool` 是内置基本类型 |
| 字面量     | 无，用 0/1                        | 有 `true` / `false`   |
| 隐式转换   | 不支持 bool 语义                  | 支持，非零即 true     |
| 头文件     | 需 `<stdbool.h>`                  | 无需额外头文件        |
| 语法简洁性 | 需包含头文件                      | 直接使用              |

> 坑：`bool` 参与 `cout` 时默认输出 1/0，看不到 true/false，需要 `boolalpha`；`sizeof(bool)` 通常是 1，但不要假设它的位宽是 1 bit。

## 3-2 字符串类型 string

**定义**：C++ 标准库中用来保存字符串的数据类型（`std::string`），需包含 `<string>`，属于 `std` 命名空间。

> 区分：`<string>` 是 C++ 的 `std::string`；`<cstring>` 是 C 风格字符串函数（`strlen` `strcpy` `strcmp`）。

**构造方式**

```cpp
#include <string>
using std::string;

string s1;                // 空串
string s2("hello");       // 构造
string s3 = "hello";      // 拷贝初始化
string s4(5, 'a');        // "aaaaa"
string s5 = s3;           // 拷贝构造
```

**常用运算**

| 运算              | 说明                        |
| ----------------- | --------------------------- |
| `+`               | 拼接，产生新串              |
| `+=`              | 追加，原地修改              |
| `> < >= <= == !=` | 按字典序逐字符比较 ASCII 值 |

```cpp
string a = "hello";
string b = "world";
a += b;                    // "helloworld"
string c = a + "!";        // "helloworld!"

if (a > b) { /* 按字典序：h < w，条件不成立 */ }
if (a == "helloworld") { }
```

**常用操作**

| 方法                  | 作用                                | 示例                      |
| --------------------- | ----------------------------------- | ------------------------- |
| `size()` / `length()` | 元素个数                            | `s.size()`                |
| `empty()`             | 是否为空（比 `size()==0` 更语义化） | `s.empty()`               |
| `find(sub)`           | 查找子串，未找到返回 `string::npos` | `s.find("ll")`            |
| `substr(pos, len)`    | 提取子串                            | `s.substr(1, 3)`          |
| `insert(pos, str)`    | 指定位置插入                        | `s.insert(2, "X")`        |
| `erase(pos, len)`     | 删除指定范围                        | `s.erase(1, 2)`           |
| `c_str()`             | 转 C 风格 `const char*`             | `printf("%s", s.c_str())` |
| `clear()`             | 清空                                | `s.clear()`               |

```cpp
string s = "hello world";
if (s.find("world") == string::npos) cout << "not found\n";
string sub = s.substr(0, 5);          // "hello"
s.insert(5, ",");                     // "hello, world"
s.erase(5, 1);                        // "hello world"
printf("%s\n", s.c_str());            // 传给 C 接口必须用 c_str()
```

**坑点**

1. `find` 找不到返回 `string::npos`（很大无符号数），**不要和 -1 直接比较**
2. `c_str()` 返回的指针在 string 修改/析构后失效
3. `substr` 越界会抛 `out_of_range`
4. `s[100]` 不检查越界（UB），`s.at(100)` 会抛异常

# 第4章 函数

## 4-1 函数概述

**定义**：把具有特定功能的一段代码封装在独立代码块中，需要通过调用执行。

**目的**

- 提高代码重用性（一次封装、多次调用）
- 增强可读性和可维护性（复杂逻辑封装，主流程简洁）
- 简化调试（只改函数内部，不动调用点）

**三要素**：函数声明、函数定义、函数调用。

## 4-2 函数声明与定义

**声明（函数原型）**：告诉编译器函数的存在及特征（返回类型、函数名、参数列表），**不包含实现**。允许多文件/模块间共享。

```cpp
int  add_int(int a, int b);   // 声明
void print();
```

**定义**：包含函数体的实际实现。

```cpp
int add_int(int a, int b)
{
    return a + b;
}

void print()
{
    // ...
}
```

> 规则：声明可多次、定义只能一次（ODR，单一定义规则）；声明与定义的返回类型、参数列表必须完全一致。

## 4-3 函数调用与参数传递

**调用形式**

```cpp
func();                 // 无返回值、无形参
func(1, 2);             // 无返回值、有形参
int x = func();         // 有返回值、无形参
int y = func(3, 4);     // 有返回值、有形参
```

**参数传递方式**

1. **按值传递**：传递实参副本，函数内修改形参不影响实参（默认）
2. **按引用传递**：传递别名，可直接修改实参，且避免拷贝
3. **按指针传递**：本质仍是按值传递（拷贝的是地址）

```cpp
void byValue(int x)  { x = 100; }   // 实参不变
void byRef(int& x)   { x = 100; }   // 实参被改
void byPtr(int* x)   { *x = 100; }  // 解引用后修改

int main()
{
    int a = 1;
    byValue(a);   // a 仍为 1
    byRef(a);     // a 变成 100
    byPtr(&a);    // a 变成 100
}
```

**函数执行流程**

1. 调用点保存返回地址、压入实参
2. 跳转到函数入口，建立栈帧，形参在栈帧中分配
3. 执行函数体
4. `return` 把返回值放入约定寄存器（x86-64 整型在 `eax`/`rax`）
5. 销毁栈帧，返回调用点继续执行

## 4-4 默认参数（缺省参数）

**定义**：在函数声明或定义时为某些参数指定默认值，调用时若未提供实参则自动使用默认值。

**语法**

```cpp
返回值类型 函数名(类型 名1 = 值1, 类型 名2 = 值2, ...) { }
```

```cpp
void log(const char* msg, int level = 1, bool flush = false)
{
    // ...
}

log("start");              // level=1, flush=false
log("warn", 2);            // flush=false
log("err", 3, true);
```

**规则（重点）**

1. **靠右原则**：某参数有默认值后，它右侧所有参数都必须有默认值

```cpp
void f(int a = 1, int b);      // 错误
void f(int a, int b = 2);      // 正确
```

2. 调用时优先使用传入实参，未传才用默认值
3. **同一参数默认值只能指定一次**：声明给了默认值，定义就不能再给（否则重定义报错）

```cpp
// a.h
void f(int x = 10);
// a.cpp
void f(int x) { }              // 正确，定义处不再写默认值
```

4. 默认参数可以是常量、全局变量、函数调用结果，但**不能是局部变量**

## 4-5 哑元参数

**定义**：函数声明/定义中只有数据类型、没有变量名的参数。函数体内不会使用，仅作占位符。

**语法**

```cpp
返回值类型 函数名(类型 名1, ..., 类型) { }   // 最后一个只有类型
```

```cpp
// 后置 ++ 重载时用它区分前/后
class Int {
    int v;
public:
    Int& operator++()      { ++v; return *this; }      // 前置
    Int  operator++(int)   { Int t = *this; ++v; return t; }  // 后置，int 是哑元
};
```

**使用场景**

- 保持接口一致性（多个重载/版本签名统一）
- 支持模板编程（不同实现按类型区分）
- 处理遗留代码（不改签名保持向后兼容）
- 纯占位（签名要求指定数量参数，但实现不需要）
- 提升可读性（显式表明「此参数刻意不用」）

## 4-6 函数重载

**定义**：同一作用域内定义多个**同名但参数列表不同**的函数。

**目的**：提高可读性与复用性，用统一接口处理不同类型/数量的数据。

**三个必备条件**

1. **同一作用域**
2. **同名**
3. **参数列表不同**（类型 / 个数 / 顺序任一不同）

**返回值不作为重载依据**（考点）

```cpp
int  f(int a);
void f(int a);      // 错误：仅返回值不同，不构成重载
```

**实现原理：名字修饰（name mangling）**
编译器在编译期把「函数名 + 参数类型」组合成唯一符号名，链接器据此区分同名函数。

```cpp
void display(int a)    { }   // 编译后符号：_Z7displayi
int  display(double a) { }   // 编译后符号：_Z7displayd
```

这就是**静态绑定（早期绑定）**：编译阶段就确定调用哪个版本。

> 对比 C 语言：C 不支持重载，因为符号名只有函数名。可用 `extern "C"` 关闭 C++ 名字修饰（常用于给 C 提供的接口）。

**调用匹配规则（顺序很重要）**

1. **精确匹配**：参数完全一致，直接命中
2. **隐式类型转换**：如 `int` → `double`
3. **最佳匹配**：优先选择不需要转换的；多个可转换路径时选「转换次数最少」的
4. 若有多个同等优的匹配 → **二义性编译错误**

```cpp
void g(int a);
void g(double a);
g(1);      // 精确匹配 g(int)
g(1.0);    // 精确匹配 g(double)
g('a');    // char → int 提升，调用 g(int)
g(1.0f);   // float→double vs float→int，前者更优 → g(double)
```

## 4-7 内联函数 inline

**定义**：普通函数前加 `inline` 即为内联函数；它本质上是**真正的函数**，会像普通函数一样做语法/类型检查。

**作用**：在编译期把函数体直接插入调用点，**省掉函数调用的压栈/跳转/返回开销**。

**关键认知**：`inline` 只是**对编译器的建议**，是否真正展开由编译器决定。

- 有时是内联函数也不展开
- 有时不是内联函数也会展开
  （所以不要用 `inline` 做「一定内联」的假设）

**语法**

```cpp
inline int max_int(int a, int b)
{
    return a > b ? a : b;
}
```

**何时使用**

- 函数体小（几行）
- 调用非常频繁
- **避免滥用**：复杂函数、递归函数内联会导致代码膨胀（指令 cache 命中率下降）

**内联函数 vs 带参宏（考点）**

| 特性       | 内联函数           | 带参宏                                       |
| ---------- | ------------------ | -------------------------------------------- |
| 展开时机   | 编译阶段           | **预处理阶段**（纯文本替换）                 |
| 类型检查   | 有，安全           | 无，易出错                                   |
| 调试       | 可打断点、看调用栈 | 难（已展开成代码）                           |
| 作用域     | 遵守类/命名空间    | 无                                           |
| 副作用风险 | 无                 | 有（如 `#define SQ(x) x*x`，`SQ(a+1)` 出错） |

```cpp
#define SQ_BAD(x)  x*x        // SQ_BAD(1+2) → 1+2*1+2 = 5，错
#define SQ_OK(x)   ((x)*(x))  // 加括号才安全，但仍无类型检查

inline int sq(int x) { return x * x; }   // 推荐
```

> 类内定义的成员函数默认隐式内联（`class A { void f(){} };`）。

# 第5章 引用

## 5-1 引用简介

**定义**：为已存在的变量创建的另一个名字（**别名**），提供对同一内存位置的另一种访问方式。

**目的**

- **节省内存开销**：避免不必要的数据复制，大对象场景尤其明显
- **提高可读性与安全性**：比指针直观，减少指针误用

**语法**

```cpp
数据类型& 引用变量名 = 引用目标;

int value = 123;
int& ref = value;      // ref 就是 value 的别名
ref = 456;             // value 也变成 456
```

**三条铁律（考点）**

1. 使用引用**必须初始化**（不能先声明后绑定）
2. 引用与引用目标的**类型必须一致**（除 `const` 引用可放宽）
3. 引用目标**一旦确定不能再修改**（不能改绑别的变量）

```cpp
int a = 1, b = 2;
int& r = a;
r = b;      // 这是赋值：a 变成 2，不是让 r 改绑到 b
```

> 底层实现：引用通常由编译器实现为**常量指针**（`int* const`），语义上透明，不占额外「可观察」空间，但 `sizeof(引用)` 得到的是目标大小。

## 5-2 引用与函数结合

**引用作函数参数**：传递的是变量别名而非副本，避免大对象拷贝，并允许函数直接修改实参。

```cpp
void swap(int& a, int& b) { int t = a; a = b; b = t; }   // 经典用法

void modifyBig(std::vector<int>& v) { v.push_back(1); }  // 避免整表拷贝
```

**引用作函数返回值**

```cpp
int g = 10;
int& getGlobal() { return g; }        // 可以返回全局变量

int& getLocal() { int x = 5; return x; }   // 错误！返回局部变量（悬空引用）

int& getStatic() { static int s = 0; return s; }   // 可以，static 生命周期到程序结束
```

规则总结：

- ✅ 可以返回全局变量
- ✅ 可以返回 `static` 修饰的局部变量
- ❌ 不能返回普通局部变量（函数结束即销毁，引用悬空）
- ✅ 可以返回引用类型的成员（但要保证对象本身还活着）

## 5-3 常引用 const reference

**定义**：用 `const` 修饰的引用，创建后**不能通过该引用修改**被引用对象。

**语法**

```cpp
const 数据类型& 别名 = 引用目标;
数据类型 const& 别名 = 引用目标;   // 两种写法等价
```

```cpp
int value = 123;
const int& cref = value;
// cref = 456;   // 错误：不可通过常引用修改
value = 789;     // 可以，通过原变量改
cout << cref;    // 789，值跟着变
```

**常引用 vs 普通引用（考点）**

| 特性                    | 普通引用 `&` | 常引用 `const &`          |
| ----------------------- | ------------ | ------------------------- |
| 能否修饰常量            | ❌            | ✅（`const int& r = 10;`） |
| 能否修饰临时值/字面量   | ❌            | ✅                         |
| 能否修改目标数据        | ✅            | ❌                         |
| 能否为 const 目标建别名 | ❌            | ✅                         |
| 是否避免拷贝            | ✅            | ✅                         |

**常引用能绑定临时量的原因**：编译器会延长临时对象的生命周期（临时量物化，寿命延长到引用的作用域结束）。

```cpp
const int& r = 10;       // OK：临时 int 被延长
const std::string& s = std::string("abc");   // OK
```

## 5-4 常引用与函数结合

```cpp
// 只读 + 避免拷贝，是「输入参数」的首选写法
void print(const std::string& s)
{
    cout << s << endl;
    // s += "x";    // 错误：常引用不可修改
}
```

**常引用作返回值**：同样可返回全局变量、`static` 局部变量，不能返回普通局部变量；返回常引用使调用方无法通过返回值修改原对象。

```cpp
const int& getCfg() { static int cfg = 42; return cfg; }
```

**参数选择决策表（工程实践）**

| 场景                                 | 推荐写法   |
| ------------------------------------ | ---------- |
| 基本类型（int/double/指针/枚举）     | 按值 `int` |
| 只读大对象（string/vector/自定义类） | `const T&` |
| 需要修改实参                         | `T&`       |
| 需要可空 / 需要改指向                | `T*`       |

## 5-5 引用与指针的区别

| 特性         | 引用 `&`                   | 指针 `*`            |
| ------------ | -------------------------- | ------------------- |
| 是否需解引用 | 不需要，直接使用           | 需要 `*` 访问值     |
| 能否为空     | ❌ 不可以                   | ✅ 可以为 `nullptr`  |
| 能否重新绑定 | ❌ 初始化后固定             | ✅ 随时改指向        |
| 初始化要求   | 必须声明时初始化           | 可以先声明后赋值    |
| 语法简洁性   | 接近普通变量               | 需处理地址与解引用  |
| 底层实现     | 通常由编译器优化为指针     | 明确存储地址        |
| 是否占内存   | 语义上不占（可能被优化掉） | 占一个指针宽度      |
| 支持算术运算 | ❌                          | ✅（`p++` 遍历数组） |

> 选择原则：能用引用就不用指针；需要「可空」「可改指向」「数组遍历」时才用指针。

# 第6章 动态内存分配与释放

## 6-1 new 与 delete 简介

**new**：C++ 运算符，运行时申请内存并返回指向该内存的指针。

- 分配内存：为变量/对象分配内存
- 初始化对象：对类类型会自动调用**构造函数**

**delete**：C++ 运算符，释放 `new` 分配的内存。

- 释放内存：归还给系统
- 清理资源：对类类型会自动调用**析构函数**

> 与 `malloc/free` 的关键区别：`new` 计算大小、有类型、会自动构造/析构，`free` 不会。

## 6-2 单个元素的分配与释放

**分配**

```cpp
int* p1 = new int;          // 未初始化（值不确定）
int* p2 = new int();        // 值初始化 → 0
int* p3 = new int(42);      // 初始化为 42
```

**释放**

```cpp
delete p1;
p1 = nullptr;               // 置空，避免野指针
```

## 6-3 数组的分配与释放

**分配**

```cpp
int* a1 = new int[10];             // 10 个元素，未初始化
int* a2 = new int[10]();           // 全部置 0
int* a3 = new int[5]{1, 2, 3};     // 前 3 个为 1,2,3，其余 0
```

**C++11 花括号初始化（重要）**

```cpp
int* a4 = new int[5]{1, 2, 3, 4, 5};
// 注意：new int[5]{} 空花括号是全 0；new int[5] 是未初始化
```

**释放（必须带 `[]`）**

```cpp
delete[] a1;
a1 = nullptr;
```

**二维数组**

```cpp
int rows = 3, cols = 4;
int** m = new int*[rows];
for (int i = 0; i < rows; ++i) m[i] = new int[cols]();

// 释放顺序反过来
for (int i = 0; i < rows; ++i) delete[] m[i];
delete[] m;
m = nullptr;
```

## 6-4 总结与常见坑

**new/delete 相对 malloc/free 的优势**

1. 按类型自动计算大小，**不用 `sizeof`**
2. 分配同时可初始化
3. 返回类型正确的指针，**不用强制转换**
4. 类类型自动调用构造/析构函数

**六大坑（高频考点）**

| 坑                                     | 说明                                       | 后果             |
| -------------------------------------- | ------------------------------------------ | ---------------- |
| `new` 配 `free` / `malloc` 配 `delete` | 分配释放机制不匹配                         | UB（未定义行为） |
| `new[]` 配 `delete`                    | 数组释放不匹配                             | UB，元素析构不全 |
| `new` 配 `delete[]`                    | 同上                                       | UB               |
| 重复 `delete`                          | 同一指针释放两次（置空后 delete 是安全的） | 崩溃             |
| 忘记释放                               | 内存泄漏                                   | 内存耗尽         |
| 释放后继续使用                         | 野指针/悬空指针                            | 崩溃、数据错乱   |

**正确姿势**

```cpp
int* p = new int(10);
// ... 使用
delete p;
p = nullptr;          // 置空，防止野指针
if (p) { /* ... */ }  // 置空后再次 delete 也安全
```

**现代 C++ 建议**：优先用**智能指针**（`std::unique_ptr` / `std::shared_ptr`）和容器（`std::vector`），用 RAII 自动管理内存，彻底避免手动 `delete`。

```cpp
#include <memory>
std::unique_ptr<int> p(new int(10));       // 离开作用域自动释放
auto v = std::make_unique<int[]>(10);      // C++14 数组
```

# 第7章 类与对象

## 7-1 面向过程 vs 面向对象

| 维度       | 面向过程              | 面向对象                   |
| ---------- | --------------------- | -------------------------- |
| 程序组织   | 一系列函数/过程的集合 | 数据与操作封装为类与对象   |
| 数据与操作 | **分离**              | **封装在一起**             |
| 关注点     | 顺序执行与流程控制    | 模块化、重用、可维护       |
| 优点       | 简单直观、开销小      | 模块化好、易扩展、安全性高 |
| 典型语言   | C                     | C++ / Java / C#            |

## 7-2 类与对象的基本概念

- **对象**：现实世界中具体存在的事物；每个对象都有**属性**（数据）和**行为**（操作）
- **类**：对一类事物的抽象描述，定义这一类对象的共性特征和行为
- **关系**：**类是对象的模板，对象是类的具体实例**

```cpp
class Fridge {          // 类：模板
public:
    int temperature;    // 属性
    void cool() { }     // 行为
};

Fridge f1, f2;          // 对象：实例
```

## 7-3 类的定义与访问权限

**语法**

```cpp
class 类名 {
访问控制权限:
    成员变量;
    成员函数;
};   // 注意分号不能省
```

```cpp
class MyClass {
public:
    int age;
    int getAge() { return age; }
private:
    int secret;
protected:
    int prot;
};
```

**三种访问权限**

| 权限        | 类内 | 派生类内 | 类外 |
| ----------- | ---- | -------- | ---- |
| `public`    | ✅    | ✅        | ✅    |
| `protected` | ✅    | ✅        | ❌    |
| `private`   | ✅    | ❌        | ❌    |

> 关键：**class 默认 private，struct 默认 public**。类中不写权限时默认是私有。

## 7-4 对象的使用方式

**栈区对象**：栈内存分配，生命周期由作用域决定，用 `.` 访问成员。

```cpp
MyClass obj;              // 自动构造
obj.age = 18;
obj.getAge();
// 离开作用域自动析构
```

**堆区对象**：堆内存分配，生命周期由程序员管理，用 `->` 访问成员。

```cpp
MyClass* p = new MyClass;
p->age = 20;
p->getAge();
delete p;
p = nullptr;
```

**对比**

| 特性     | 栈区对象               | 堆区对象               |
| -------- | ---------------------- | ---------------------- |
| 内存位置 | 栈                     | 堆                     |
| 生命周期 | 系统自动管理（作用域） | 程序员手动 `delete`    |
| 访问方式 | `.`                    | `->`                   |
| 优点     | 自动释放、快           | 动态大小、生命周期灵活 |
| 缺点     | 受作用域限制、栈空间小 | 易泄漏、分配慢         |

## 7-5 类的大小

**四条结论（考点密集）**

1. **空类占 1 字节**
   为了保证每个对象在内存中有**唯一地址**（对象身份识别），`sizeof(Empty) == 1`。

2. **访问权限不占大小**
   `public/private/protected` 只是编译期控制，运行期不占内存。

3. **成员函数不占类的大小**
   函数代码存在**代码段**，所有对象共享，不随对象复制。

4. **成员变量占类的大小**，并受**内存对齐**影响。

```cpp
class Empty {};                        // sizeof = 1
class A { int a; char c; };            // 通常 8（对齐填充 3 字节）
class B { char c; int a; };            // 通常 8
class C { char c; double d; };         // 通常 16
class D { int a; void f() {} };        // sizeof = 4（函数不占）
```

**有虚函数的类**：会多一个**虚函数表指针 vptr**（64 位下 8 字节）。

```cpp
class E { virtual void f() {} int a; };   // 8 + 4 + 填充 → 通常 16
```

**对齐规则速记**

- 每个成员起始地址是其自身对齐值的整数倍
- 结构体总大小是其**最大对齐值**的整数倍
- 可用 `#pragma pack(1)` 或 `alignas` 调整，但会影响性能

# 第8章 构造函数与析构函数

## 8-1 构造函数

**定义**：一种特殊的成员函数，用于在创建对象时初始化对象状态（成员变量初始化、申请资源等）。

**三个特征（必记）**

1. 名字与类名**完全相同**
2. **没有返回值类型**（连 `void` 都没有）
3. **可以被重载**

**作用**

- 构建对象的基本状态，确保对象处于有效、一致的状态
- 申请资源（动态内存、打开文件等）
- 完成成员变量初始化

**语法**

```cpp
class 类名 {
public:
    类名(参数列表) : 初始化列表 {
        // 构造函数体
    }
};
```

```cpp
class Student {
public:
    Student() { }                              // 无参构造
    Student(int id, const char* n) { }         // 有参构造
private:
    int  m_id;
    std::string m_name;
};
```

**分类**

- 默认构造函数
- 有参构造函数
- 拷贝构造函数

> 构造函数通常声明为 `public`，否则类外无法创建对象（单例模式正是借此禁止外部构造）。

## 8-2 默认构造函数

**定义**：不需要提供参数即可创建对象的构造函数。包括两种形式：

1. 完全没有参数
2. 所有参数都有默认值

**隐式默认构造函数**：用户**没有定义任何构造函数**时，编译器自动生成一个无参默认构造函数，不做额外操作。

**显式默认构造函数**：用户自己定义的默认构造函数，可自定义初始化逻辑。

```cpp
// 形式一：无参
class A {
public:
    A() { m_x = 0; }
private:
    int m_x;
};

// 形式二：全参数有默认值，也可当默认构造用
class B {
public:
    B(int x = 0, int y = 0) : m_x(x), m_y(y) { }
private:
    int m_x, m_y;
};

B b;        // 用 B(int=0, int=0)
```

**关键规则（高频考点）**

- 一旦用户定义了**任何一个**构造函数（包括有参构造），编译器**不再**生成隐式默认构造函数
- 此时若还想无参创建对象，必须显式写 `A() = default;` 或自己实现无参构造

```cpp
class C {
public:
    C(int x) { }        // 定义了这个，就没有隐式默认构造了
};
C c1;                   // 错误：没有默认构造函数
C c2(10);               // 正确

// 修法：显式恢复
class D {
public:
    D() = default;
    D(int x) { }
};
```

**类型特性工具**

```cpp
#include <type_traits>
static_assert(std::is_default_constructible<A>::value, "A 必须可默认构造");
```

## 8-3 有参构造函数与 explicit

**定义**：接受一个或多个参数，用传入参数初始化对象，允许创建对象时定制状态。

**作用**

- 创建对象时直接给成员赋初值，避免「先默认构造再手动赋值」
- 提高灵活性，对象状态创建时即明确可控

**实例化时的调用方式**

栈区：

```cpp
类名 对象名;                     // 调默认构造
类名 对象名(参数);               // 调有参构造（推荐）
类名 对象名 = 类名(参数);        // 显式临时对象 + 拷贝（可被优化）
类名 对象名 = 参数;              // 仅一个参数，隐式转换构造
```

堆区：

```cpp
类名* p = new 类名;              // 默认构造
类名* p = new 类名(参数);        // 有参构造
```

**参数类型四种形式**

| 类型     | 写法                      | 优点              | 适用场景         |
| -------- | ------------------------- | ----------------- | ---------------- |
| 普通参数 | `A(int x)`                | 简单直观          | 常规传值         |
| 默认参数 | `A(int x = 0)`            | 灵活、减少重载    | 多种初始化方式   |
| 哑元参数 | `A(int, int)` 或 `A(int)` | 满足签名/避免歧义 | 接口兼容、特化   |
| 引用参数 | `A(const Big& b)`         | 避免大对象拷贝    | 大对象、复杂结构 |

**explicit 关键字（重点）**

作用：**禁止构造函数的隐式类型转换**，只允许显式构造。

```cpp
class MyString {
public:
    explicit MyString(int size) { }   // 禁止隐式转换
    // 不加 explicit 时：MyString s = 10; 会隐式把 10 转成 MyString
};

MyString s1(10);            // ✅ 显式，OK
MyString s2 = MyString(10); // ✅ 显式临时对象
MyString s3 = 10;           // ❌ 被 explicit 禁止（不加 explicit 时合法）
```

**使用场景**

- 防止意外的隐式转换导致逻辑错误
- 提高安全性，明确允许/禁止的转换
- 增强可读性，转换意图清晰

> 规范建议：**单参数构造函数默认加 `explicit`**（除非你确实需要隐式转换，例如 `std::string` 从 `const char*` 的构造）。

## 8-4 初始化列表

**定义**：构造函数中用来在**函数体执行之前**初始化成员变量的机制。

**语法**

```cpp
类名(参数列表) : 成员1(值1), 成员2(值2), ... {
    构造函数体
}
```

```cpp
class Point {
public:
    Point(int x, int y) : m_x(x), m_y(y) { }   // 初始化列表
private:
    int m_x, m_y;
};
```

**两个好处**

1. **效率更高**：直接构造/初始化，避免「先默认构造再赋值」的二次开销
2. 能解决某些**无法在函数体内赋值**的情况

**必须使用初始化列表的四类成员（考点）**

| 成员类型               | 原因                                           |
| ---------------------- | ---------------------------------------------- |
| `const` 成员           | 常量必须初始化，不能赋值                       |
| 引用成员               | 引用必须绑定时初始化，且不能重新绑定           |
| 无默认构造的类类型成员 | 函数体内赋值需要先默认构造，但没有默认构造     |
| 成员变量名与形参同名   | 需用 `: m_x(x)` 明确区分，否则变成自己赋值自己 |

```cpp
class Bad {
    const int  c;        // 必须初始化列表
    int&       r;        // 必须初始化列表
    std::string s;       // 有默认构造，可以函数体赋值，但初始化列表更优
public:
    Bad(int x, int& ref) : c(x), r(ref) { }   // ✅
    // Bad(int x, int& ref) { c = x; r = ref; }  // ❌ const/引用不能赋值
};

class Shadow {
    int m_age;
public:
    // 形参也叫 age 时，必须 m_age(age)，写成 m_age = age 会变成自赋值
    Shadow(int age) : m_age(age) { }
};
```

**初始化顺序（高频坑）**

- 成员按**类中声明顺序**初始化，与初始化列表书写顺序**无关**
- 基类先于成员，成员先于构造函数体

```cpp
class Order {
    int b;   // 实际先初始化 b
    int a;
public:
    Order(int x) : a(x), b(a) { }   // 看起来先 a，实际先 b，b(a) 用了未初始化的 a → UB
};
```

> 建议：初始化列表的书写顺序**始终与成员声明顺序一致**，并开 `-Wall -Wextra` 让编译器告警。

## 8-5 析构函数

**定义**：类的一种特殊成员函数，对象生命周期结束时**自动调用**，用于释放资源（动态内存、网络连接、文件句柄等）。

**触发时机**

1. 对象离开作用域（局部对象在函数返回时）
2. 堆对象被 `delete` / `delete[]`
3. 程序结束时，全局/静态对象的析构函数被自动调用

**语法**

```cpp
class 类名 {
public:
    ~类名() {
        // 清理工作
    }
};
```

**三个特征**

1. 名字与类名相同，前面加 `~`
2. **没有返回值类型**，也**不接受任何参数**
3. **每个类只能有一个析构函数，不能重载**

**典型用法：释放 new 出来的资源**

```cpp
class Buffer {
public:
    Buffer(int n) : m_data(new int[n]), m_n(n) { }
    ~Buffer() { delete[] m_data; m_data = nullptr; }   // 自动回收
private:
    int* m_data;
    int  m_n;
};
```

**为什么析构函数通常要声明为 virtual**：见第 15 章「虚析构函数」——通过基类指针删除派生类对象时必须虚析构，否则只调用基类析构，派生类资源泄漏。

## 8-6 构造函数与析构函数的调用顺序

**堆区对象**

- 构造函数：`new` 时调用
- 析构函数：`delete` 时调用

**栈区对象**

- 构造函数：实例化对象（定义处）时调用
- 析构函数：**后进先出（LIFO）**
  - 先实例化的对象**后**析构
  - 后实例化的对象**先**析构

```cpp
class T {
public:
    T(const char* n) : name(n) { cout << "ctor " << name << endl; }
    ~T() { cout << "dtor " << name << endl; }
private:
    std::string name;
};

void f()
{
    T a("a");     // ctor a
    T b("b");     // ctor b
}                 // dtor b → dtor a（逆序）
```

## 8-7 类中包含成员对象 / 指针成员

**成员对象（类类型成员）**

| 阶段 | 顺序                                       |
| ---- | ------------------------------------------ |
| 构造 | 先成员对象的构造函数，再当前对象的构造函数 |
| 析构 | 先当前对象的析构函数，再成员对象的析构函数 |

```cpp
class Inner {
public:
    Inner()  { cout << "Inner ctor\n"; }
    ~Inner() { cout << "Inner dtor\n"; }
};

class Outer {
    Inner m_inner;      // 成员对象
public:
    Outer()  { cout << "Outer ctor\n"; }
    ~Outer() { cout << "Outer dtor\n"; }
};

Outer o;   // Inner ctor → Outer ctor，析构时 Outer dtor → Inner dtor
```

> 本质：是完全的「栈式」生命周期——编译器自动生成 `Outer` 的构造/析构，用初始化列表构造成员，析构时按声明逆序销毁成员。

**指针成员（重要陷阱）**

指针成员**不会自动释放所指对象**，必须手写析构。

```cpp
class Bad {
    int* p;
public:
    Bad() : p(new int(0)) { }        // 有 new
    // 没有析构 → 每个对象泄漏 4 字节
};

class Good {
    int* p;
public:
    Good() : p(new int(0)) { }
    ~Good() { delete p; p = nullptr; }
};
```

**含指针成员的类还必须考虑拷贝**：默认拷贝是浅拷贝（只复制指针值），会导致双重释放。需要自己实现**深拷贝**（拷贝构造 + 拷贝赋值），见第 9 章。

**多个成员对象时的顺序**：按**声明顺序**构造，按**声明逆序**析构。

# 第9章 拷贝控制（拷贝构造 / 拷贝赋值 / this）

## 9-1 拷贝构造函数

**定义**：一种特殊的构造函数，用**一个已存在的同类对象**初始化**新对象**。

**语法**

```cpp
class 类名 {
public:
    类名(const 类名& other) {              // 标准形式
        // 拷贝逻辑
    }

    类名(const 类名& other)
        : 成员1(other.成员1), 成员2(other.成员2) { }   // 带初始化列表
};
```

```cpp
class Student {
public:
    Student(const Student& other) : m_id(other.m_id), m_name(other.m_name)
    {
        cout << "copy ctor\n";
    }
private:
    int m_id;
    std::string m_name;
};
```

**为什么参数必须是 `const 类名&`（考点）**

- **必须用引用**：若按值传参，传参本身又要拷贝一次 → 无限递归
- **加 const**：既避免意外修改源对象，又能接收 const 对象和临时对象
- **用引用**：避免不必要的拷贝，提高效率

**触发时机（三个）**

1. 用同类对象初始化新对象：`A b = a;` 或 `A b(a);`
2. 对象按值传参给函数
3. 函数按值返回对象（可能被 RVO/NRVO 优化掉，但语义上仍是拷贝构造）

```cpp
void takeByValue(Student s) { }   // 传参时拷贝构造
Student make() { Student s; return s; }   // 返回值，可能被优化
```

**关键规则**

- 没显式定义时，编译器自动生成**默认拷贝构造函数**
- 默认版本执行**逐成员浅拷贝**（对每个成员调用其拷贝构造/赋值）
- 类中有动态资源（指针）时，默认浅拷贝会出问题 → 必须自实现**深拷贝**

## 9-2 浅拷贝与深拷贝

**浅拷贝**：逐字节/逐成员复制，指针成员只复制**地址**，两个对象共享同一块堆内存。

**引发的问题**

| 问题                        | 说明                                                     |
| --------------------------- | -------------------------------------------------------- |
| **双重释放（double free）** | 两个对象析构时都 `delete` 同一块内存 → 崩溃              |
| **内存泄漏**                | 一个对象释放后，另一个仍持悬空指针；或指针被覆盖前未释放 |
| **数据串改**                | 一个对象改数据，另一个跟着变，违背值语义                 |

**深拷贝**：为新对象**重新申请独立内存**，把内容复制过去，两个对象各持一份。

```cpp
class Person {
public:
    // 构造
    Person(const char* n) : m_name(new std::string(n)) { }

    // 深拷贝构造：为新对象申请新内存
    Person(const Person& other) : m_name(new std::string(*other.m_name)) { }

    // 深拷贝赋值
    Person& operator=(const Person& other)
    {
        if (this != &other) {
            delete m_name;                                   // ① 释放旧空间
            m_name = new std::string(*other.m_name);         // ② 申请新空间 + 拷贝值
        }
        return *this;
    }

    ~Person() { delete m_name; m_name = nullptr; }
private:
    std::string* m_name;    // 指针成员
};
```

**深拷贝赋值四步法（记牢）**

1. 自赋值检查 `if (this != &other)`
2. 释放自身旧资源
3. 申请新资源并拷贝内容
4. 返回 `*this`

**对比表**

| 特性     | 浅拷贝               | 深拷贝               |
| -------- | -------------------- | -------------------- |
| 内存分配 | 不分配，只复制指针   | 分配新内存，复制内容 |
| 数据共享 | 共享同一块内存       | 各自独立             |
| 安全性   | 有泄漏/双重释放风险  | 安全                 |
| 适用场景 | 简单类型、无资源管理 | 含动态资源的类       |

> 更稳妥的写法（异常安全）：**copy-and-swap**
>
> ```cpp
> Person& operator=(Person other) {   // 传值，已拷贝一份
>  std::swap(m_name, other.m_name);
>  return *this;
> }
> ```

## 9-3 this 指针

**定义**：C++ 中隐藏在类的**非静态成员函数形参表**中的指针，类型为 `类名* const`，指向**调用该函数的当前对象自身**。

```cpp
// 代码层面
class A { void f(int x) { } };

// 编译层面（编译器实际看到的）
class A { void f(A* const this, int x) { } };
```

**五个使用注意（考点）**

1. `this` 不能显式出现在成员函数的**形参表**中
2. `this` 不能显式出现在构造函数的**初始化列表**中
3. `this` 只能在**类内部**使用
4. `this` 不能在**全局作用域**或**静态成员函数**中使用（静态函数不属于任何对象，没有 this）
5. `this` 是**指针**，用 `->`；`*this` 是对象本身/引用

**必须用 this 的四个场合**

1. **成员变量与形参同名**

```cpp
class A {
    int age;
public:
    A(int age) { this->age = age; }   // 区分形参与成员
};
```

2. **返回当前对象的引用/指针**（链式调用）

```cpp
class Counter {
    int v = 0;
public:
    Counter& add(int n) { v += n; return *this; }   // 返回 *this
};

Counter c;
c.add(1).add(2).add(3);    // 链式调用
```

3. **销毁自身（delete this）**

```cpp
class SelfDelete {
public:
    void destroy() { delete this; }   // 自杀，调用后不能再访问任何成员
};
```

> 危险操作：`delete this` 后对象已销毁，函数内**不能**再访问成员、不能 return 成员值；且对象必须是 `new` 出来的。

4. **在成员函数中把自身作为参数传出**

```cpp
void registerSelf() { pool.add(this); }
```

**`this` 与 const**

- 常函数中 `this` 的类型是 `const 类名* const`，因此不能修改成员
- `mutable` 成员在常函数中仍可通过 `this` 修改

## 9-4 拷贝赋值函数（拷贝赋值运算符）

**定义**：又称拷贝赋值运算符，把**一个已存在对象的值赋给另一个已存在对象**（不是创建新对象）。

**语法**

```cpp
class 类名 {
public:
    类名& operator=(const 类名& other) {
        if (this != &other) {
            // 拷贝赋值操作
        }
        return *this;
    }
};
```

**三个要点**

1. **自赋值检查**：必须判断 `this != &other`，否则 `a = a` 时先释放自己的资源再拷贝，会读已释放内存
2. **返回 `*this` 的引用**：支持链式赋值 `a = b = c`
3. **动态资源管理**：含指针成员时必须深拷贝，且释放旧资源

**浅拷贝 vs 深拷贝**：与拷贝构造同理；默认拷贝赋值是浅拷贝。

**拷贝构造 vs 拷贝赋值的区别（高频考点）**

| 维度             | 拷贝构造             | 拷贝赋值                       |
| ---------------- | -------------------- | ------------------------------ |
| 何时调用         | **创建新对象**时     | 两个对象**都已存在**时         |
| 是否新建对象     | 是                   | 否，修改已有对象               |
| 签名             | `类名(const 类名&)`  | `类名& operator=(const 类名&)` |
| 返回值           | 无（构造函数）       | 返回 `*this` 引用              |
| 是否需释放旧资源 | 不需要（还没有资源） | **必须**先释放自身旧资源       |

```cpp
A a;            // 默认构造
A b(a);         // 拷贝构造（新对象）
A c = a;        // 拷贝构造（不是赋值！初始化语法）
A d;
d = a;          // 拷贝赋值（d 已存在）
```

> 记忆口诀：**带「初始化」的是拷贝构造，带「=」但对象已存在的是拷贝赋值**。`A c = a;` 是初始化，所以是拷贝构造。

## 9-5 C++ 四大核心函数对比（Rule of Three）

| 特性     | 构造函数               | 析构函数                            | 拷贝构造函数               | 拷贝赋值函数                         |
| -------- | ---------------------- | ----------------------------------- | -------------------------- | ------------------------------------ |
| 定义     | 创建对象并初始化成员   | 释放对象占用的资源                  | 用已有对象创建**新对象**   | 把已有对象赋值给**已存在对象**       |
| 调用时机 | 创建对象时             | 生命周期结束（离开作用域 / delete） | 创建对象并用另一对象初始化 | 已存在对象被赋值为另一对象           |
| 返回值   | 无                     | 无                                  | 无                         | 返回当前对象引用 `类名&`             |
| 参数     | 可重载，参数灵活       | **无参数**                          | `const 类名&`              | `const 类名&`                        |
| 可否省略 | 可，编译器生成默认构造 | 可，生成默认析构                    | 可，生成默认（浅拷贝）     | 可，生成默认（浅拷贝）               |
| 作用范围 | 初始化对象状态         | 清理资源                            | 初始化新对象为副本         | 修改已有对象状态为副本               |
| 注意事项 | 可重载；避免资源泄漏   | 避免重复释放；确保资源释放          | 含动态资源必须深拷贝       | 必须自赋值检查；含动态资源必须深拷贝 |

**三法则（Rule of Three）**

> 只要类需要自定义**析构函数、拷贝构造函数、拷贝赋值函数**中的**任意一个**，通常三个都需要自定义。
> 原因：需要自定义析构说明类管理了资源；默认的拷贝成员会做浅拷贝，必然出错。

**五法则（C++11 扩展）**：再加上**移动构造函数**和**移动赋值函数**。

```cpp
class Res {
public:
    Res(Res&& other) noexcept;              // 移动构造
    Res& operator=(Res&& other) noexcept;   // 移动赋值
};
```

**零法则（Rule of Zero，最推荐）**：不在类里管理裸资源，用 `std::string`、`std::vector`、`std::unique_ptr` 等 RAII 类型，四个函数全部用默认版本即可。

# 第10章 常函数、常对象与静态成员

## 10-1 常函数（const 成员函数）

**定义**：用 `const` 修饰的成员函数。

**语法**

```cpp
class 类名 {
    返回值类型 函数名(形参表) const { }
};
```

```cpp
class Point {
public:
    int getX() const { return m_x; }    // 常函数
    void setX(int x) { m_x = x; }       // 非常函数
private:
    int m_x;
};
```

**三个注意（考点）**

1. `const` 写在**形参表后面**，不是返回值前面
2. 常函数中的 `const` 修饰的是 **`this` 指针**（`const 类名* const this`），所以不能修改成员变量
3. **常函数版本与非常函数版本可以构成重载**

```cpp
class A {
public:
    void f()       { cout << "non-const\n"; }
    void f() const { cout << "const\n"; }
};

A a;             // 非常对象 → 优先调非常函数版本
const A ca;      // 常对象 → 只能调常函数版本
```

**作用**：保证函数不修改对象状态（成员变量），提高安全性，尤其在常对象/只读接口场景。

**在常函数中修改成员：`mutable`**

```cpp
class Logger {
public:
    void log() const { ++m_count; }        // 常函数里改 mutable 成员，合法
private:
    mutable int m_count = 0;               // 逻辑上不影响对象「值语义」的统计量
};
```

> `mutable` 仅用于「逻辑上不改变对象状态」的场景（缓存、计数器、互斥锁），不要滥用。

**调用优先级**

- 有非常函数版本 + 常函数版本 → **非常对象优先调非常版本**
- 只有常函数版本 → 调常函数版本
- 常对象 → **只能**调常函数

## 10-2 常对象

**定义**：用 `const` 修饰的对象，创建后状态不能修改（不能调用会修改成员的非常函数）。

**语法**

```cpp
const 类名 对象名;
const 类名* 指针 = new 类名;        // 注意：指向常对象的指针
```

```cpp
class Point {
public:
    int  getX() const { return m_x; }
    void setX(int x) { m_x = x; }
private:
    int m_x = 0;
};

const Point p;
p.getX();       // ✅ 常函数可以调用
// p.setX(5);   // ❌ 非常函数不能对常对象调用
```

**三条规则（考点）**

1. 常对象**只能调用常函数**，不能调用非常函数
2. 非常对象**优先**调非常函数；没有非常函数时才调常函数
3. 常对象不能修改成员；非常对象可以

**const 对象与指针/引用的常见混淆**

| 写法                     | 含义                                                |
| ------------------------ | --------------------------------------------------- |
| `const A a;`             | 对象本身是 const                                    |
| `const A* p = &a;`       | 指向常对象的指针，不能通过 p 改对象；p 本身可改指向 |
| `A* const p = &a;`       | p 是常指针，p 不能改指向；可通过 p 改对象           |
| `const A* const p = &a;` | 两者都 const                                        |
| `A const& r = a;`        | 常引用，不能通过 r 改对象                           |

> 口诀：`const` 修饰它**左边**的东西；左边没有则修饰右边。`const A* p` → `*p` 是 const；`A* const p` → `p` 是 const。

## 10-3 静态成员变量

**定义**：用 `static` 修饰的类成员，**属于类本身**而不是某个对象。

**语法：类内声明，类外定义并初始化**

```cpp
class 类名 {
    static 数据类型 变量名;      // 类内声明（不能初始化）
};

数据类型 类名::变量名 = 初始值;   // 类外定义 + 初始化
```

```cpp
class Counter {
public:
    Counter() { ++s_count; }
    static int getCount() { return s_count; }
private:
    static int s_count;          // 声明
};

int Counter::s_count = 0;        // 定义并初始化（不能写 static）
```

**四条注意（高频考点）**

1. 静态成员变量**必须在类外定义/初始化**，类内不能初始化（`inline static` 例外，见下）
2. 类外定义时**不能写 `static`**，但必须加 `类名::`
3. **所有对象共享同一份**静态成员变量（不属于某个对象）
4. 若是 `private/protected`，类外不能直接访问，需通过公有静态成员函数等接口访问

**C++17 起：`inline static` 可就地初始化**

```cpp
class Counter {
public:
    inline static int s_count = 0;   // C++17 允许，不再需要在 .cpp 里定义
};
```

**三种访问方式**

```cpp
Counter::getCount();       // 类名::（推荐）
Counter c; c.getCount();   // 对象.
Counter* p = &c; p->getCount();   // 指针->
```

> `sizeof(类)` 不包含静态成员变量（它不随对象分配，存在于静态存储区）。

## 10-4 静态成员函数

**定义**：用 `static` 修饰的成员函数，属于类本身，不依赖对象。

**语法**：类内定义或类内声明+类外定义都可

```cpp
class 类名 {
    static 返回值类型 函数名(形参表) { }        // 类内定义
    static 返回值类型 函数名(形参名);            // 类内声明
};

返回值类型 类名::函数名(形参名) { }             // 类外定义（不写 static）
```

**四个特点（考点）**

1. **只能访问静态成员变量和其他静态成员函数**
2. **没有 `this` 指针**，因此不能直接访问非静态成员
3. **不依赖具体对象实例**，可用 `类名::函数名()` 直接调用
4. 不能是 `virtual`、不能是 `const`（没有 this 可修饰）

**能否访问对照表**

| 访问目标       | 静态成员函数能否访问 | 原因               |
| -------------- | -------------------- | ------------------ |
| 静态成员变量   | ✅                    | 属于类，不依赖对象 |
| 非静态成员变量 | ❌                    | 需要对象实例       |
| 静态成员函数   | ✅                    | 同属类             |
| 非静态成员函数 | ❌                    | 需要对象实例       |

**若静态函数需要访问非静态成员**：必须显式把对象作为参数传入

```cpp
class A {
    int m_v;
public:
    static void show(const A& obj) { cout << obj.m_v; }   // 传对象进来
};
```

## 10-5 静态成员使用场景

| 场景         | 用途                                |
| ------------ | ----------------------------------- |
| 计数器       | 统计对象创建/销毁数量（`s_count`）  |
| 全局配置管理 | 共享配置项，避免重复设置            |
| 资源管理     | 共享单一资源/状态，保证全局唯一     |
| 工具函数     | 与对象无关的通用功能，直接类名调用  |
| 单例模式     | 静态成员变量 + 静态函数控制唯一实例 |
| 日志记录     | 全局日志流、统一日志接口            |
| 缓存         | 存储常用数据，减少重复计算          |

```cpp
// 计数器完整示例
class Obj {
public:
    Obj()  { ++s_live; ++s_total; }
    ~Obj() { --s_live; }
    static int live()  { return s_live; }
    static int total() { return s_total; }
private:
    static int s_live;
    static int s_total;
};
int Obj::s_live = 0;
int Obj::s_total = 0;
```

# 第11章 设计模式之单例模式

## 11-1 设计模式简介

**定义**：软件开发中针对**反复出现的问题**总结出的通用解决方案，是大量开发者长期实践的沉淀。

**三大分类**

| 类别   | 关注点                               | 代表模式                                           |
| ------ | ------------------------------------ | -------------------------------------------------- |
| 创建型 | 对象的创建过程，提高灵活性与可扩展性 | 单例、工厂方法、抽象工厂、建造者、原型             |
| 结构型 | 类与对象的组合，优化系统结构         | 适配器、桥接、组合、装饰器、外观、享元、代理       |
| 行为型 | 对象间通信与职责分配                 | 模板方法、策略、观察者、状态、命令、责任链、迭代器 |

**创建型模式速查**

| 模式     | 描述                                           |
| -------- | ---------------------------------------------- |
| 单例     | 确保一个类只有一个实例，并提供全局访问点       |
| 工厂方法 | 定义创建对象的接口，由子类决定实例化哪个类     |
| 抽象工厂 | 创建一系列相关/依赖对象的接口，无需指定具体类  |
| 建造者   | 构建与表示分离，同一构建过程可产生不同表示     |
| 原型     | 用原型实例指定创建种类，通过复制原型创建新对象 |

**结构型模式速查**

| 模式   | 描述                               |
| ------ | ---------------------------------- |
| 适配器 | 把一个类的接口转换成客户希望的接口 |
| 桥接   | 抽象与实现分离，各自独立变化       |
| 组合   | 统一方式处理单个对象和对象组合     |
| 装饰器 | 动态给对象添加职责，不影响其他对象 |
| 外观   | 统一接口访问子系统的一群接口       |
| 享元   | 共享技术支撑大量细粒度对象         |
| 代理   | 为其他对象提供代理以控制访问       |

**行为型模式速查**

| 模式     | 描述                                       |
| -------- | ------------------------------------------ |
| 模板方法 | 定义算法骨架，部分步骤延迟到子类           |
| 策略     | 封装一系列算法，可互相替换                 |
| 观察者   | 一对多依赖，状态变化时通知所有依赖者       |
| 状态     | 内部状态改变时改变行为                     |
| 命令     | 把请求封装成对象，可参数化                 |
| 责任链   | 多对象都有机会处理请求，解耦发送者与接收者 |
| 迭代器   | 顺序访问聚合元素而不暴露内部表示           |

## 11-2 单例模式简介

**定义**：一种创建型设计模式，确保一个类**只有一个实例**，并提供**全局访问点**。

**两大特征**

1. **唯一性**：整个应用生命周期内，类实例只有一个
2. **全局访问**：通过统一接口访问，避免重复创建

**核心思想**

1. **控制实例化过程**
   - 构造函数设为 `private`（或 `protected`），禁止外部 `new` / 栈对象
   - 类的内部负责创建和管理唯一实例
2. **提供唯一访问入口**
   - 提供 `static` 方法返回唯一实例
   - 所有代码都通过该入口访问

**为何要禁用拷贝**：还要把拷贝构造、拷贝赋值声明为 `delete`，否则 `A b = A::getInstance();` 能造出第二个对象。

## 11-3 饿汉式（Eager）

**思想**：类加载（程序启动）时就把对象创建好。

**三步**

1. 构造函数私有化
2. 私有静态成员变量维护唯一对象
3. 公有静态成员函数返回该对象

```cpp
class Singleton {
public:
    static Singleton& getInstance() { return s_instance; }

    Singleton(const Singleton&) = delete;              // 禁止拷贝构造
    Singleton& operator=(const Singleton&) = delete;   // 禁止拷贝赋值

private:
    Singleton() { }                                    // 私有构造
    static Singleton s_instance;                       // 唯一对象
};

Singleton Singleton::s_instance;                       // 类外定义（启动即构造）
```

**特点**

- 类加载时创建，**线程安全**（静态初始化由运行时保证，C++11 起无竞态）
- 无论是否使用都一直占用内存
- 实现简单，无锁

## 11-4 懒汉式（Lazy）

**思想**：**第一次使用时才创建**。

**三步**

1. 构造函数私有化
2. 私有静态**指针**成员变量，初始为 `nullptr`
3. 公有静态函数中：首次调用创建并返回，后续直接返回已有对象

**基础版（非线程安全）**

```cpp
class Singleton {
public:
    static Singleton* getInstance() {
        if (s_instance == nullptr)
            s_instance = new Singleton();    // 首次才创建
        return s_instance;
    }
    Singleton(const Singleton&) = delete;
    Singleton& operator=(const Singleton&) = delete;
private:
    Singleton() { }
    static Singleton* s_instance;
};
Singleton* Singleton::s_instance = nullptr;
```

**线程安全版（C++11 局部静态，推荐）**

```cpp
class Singleton {
public:
    static Singleton& getInstance() {
        static Singleton instance;    // C++11 保证：首次执行到此处才构造，且线程安全
        return instance;
    }
    Singleton(const Singleton&) = delete;
    Singleton& operator=(const Singleton&) = delete;
private:
    Singleton() { }
    ~Singleton() { }
};
```

> 这是**最推荐**的写法：线程安全（magic static）、延迟初始化、自动析构，无需手动加锁/管理内存。

**双检锁版（了解即可）**

```cpp
#include <mutex>
static Singleton* getInstance() {
    if (s_instance == nullptr) {                 // 第一次检查，避免每次加锁
        std::lock_guard<std::mutex> lock(s_mtx);
        if (s_instance == nullptr) {             // 第二次检查，防止重复创建
            s_instance = new Singleton();
        }
    }
    return s_instance;
}
```

> 注意：C++11 之前双检锁有指令重排风险，需 `atomic` + 内存序；C++11 用局部静态最省事。

## 11-5 饿汉式 vs 懒汉式

| 特性     | 饿汉式                       | 懒汉式                         |
| -------- | ---------------------------- | ------------------------------ |
| 创建时间 | 类加载时                     | 第一次使用时                   |
| 线程安全 | ✅ 天然安全                   | 需要额外处理（局部静态可解决） |
| 内存占用 | 始终占用                     | 按需分配                       |
| 启动开销 | 启动稍慢                     | 首次调用稍慢                   |
| 适用场景 | 对象必须始终存在、创建成本低 | 对象可能不用、创建成本高       |

**其他要点**

- 单例的**析构**：饿汉式在程序结束时析构；`new` 出来的懒汉式需显式 `delete` 或干脆不管（进程结束回收）
- 单例不是「万能」：会引入全局状态、难以测试（依赖注入更好）、多线程下要保证内部状态也线程安全
- 单例 vs 全局变量：单例可控（延迟、唯一、可限制访问），全局变量无法约束

# 第12章 友元

## 12-1 友元简介

**定义**：C++ 中的一种机制，允许**特定的函数或类**访问另一个类的 `private` 和 `protected` 成员。

**特点**

- **打破封装性**，提供对内部成员的直接访问
- 用于特定场景提高灵活性
- 友元关系是**单向**的，**不具有交换性、传递性和继承性**

**适用场景**：需要在类外部访问类的私有/保护成员（如运算符重载的 `<<`、`>>`）。

**三种分类**

1. **友元函数**：全局函数作为某个类的友元
2. **友元成员函数**：一个类的成员函数作为另一个类的友元
3. **友元类**：一个类作为另一个类的友元

## 12-2 友元函数

**定义**：全局函数被声明为类的友元后，可访问该类的所有成员（含 private/protected）。

**语法**

```cpp
class 类名 {
    friend 返回值类型 函数名(形参);     // 类内声明友元函数
};

返回值类型 函数名(形参) { }             // 类外（全局）定义
```

```cpp
class Complex {
public:
    Complex(double r = 0, double i = 0) : m_r(r), m_i(i) { }
    friend std::ostream& operator<<(std::ostream& out, const Complex& c);   // 友元声明
private:
    double m_r, m_i;
};

std::ostream& operator<<(std::ostream& out, const Complex& c)              // 全局定义
{
    out << c.m_r << "+" << c.m_i << "i";      // 直接访问私有成员
    return out;
}
```

**注意**

- 友元函数可以**直接访问静态成员变量**
- 访问**非静态成员变量**时，必须有一个**类类型的形参**（否则不知道该访问哪个对象）
- 友元声明只是「授权」，函数本身仍是全局函数，不在类的作用域内

## 12-3 友元成员函数

**定义**：把一个类的**某个成员函数**声明为另一个类的友元，使其能访问另一个类的私有/保护成员。

**语法**

```cpp
class B;    // 前置声明（必须）

class A {
public:
    void func(B& b);        // 声明成员函数
};

class B {
    friend void A::func(B& b);   // 声明 A::func 为友元成员函数
private:
    int m_secret;
};

void A::func(B& b) { b.m_secret = 1; }   // 类外实现
```

**两个特点**

1. 需要在**类外实现**该成员函数
2. 需要**前置声明**被引用的类（否则 `A::func` 无法解析）

## 12-4 友元类

**定义**：把一个类声明为另一个类的友元，该类的**所有成员函数**都能访问对方私有/保护成员。

**语法**

```cpp
class 类名1 {
    friend class 类名2;      // 声明 类名2 是 类名1 的友元
};
```

```cpp
class Storage {
    friend class Manager;      // Manager 的所有成员函数都能访问 Storage 私有成员
private:
    int m_data[10];
};

class Manager {
public:
    void clear(Storage& s) {
        for (int i = 0; i < 10; ++i) s.m_data[i] = 0;   // 可直接访问
    }
};
```

**特点**

- 友元关系**单向**：A 是 B 的友元 ≠ B 是 A 的友元
- 友元类可访问对方的**所有**成员

## 12-5 使用友元的注意事项

1. **不具有交换性**：A 是 B 的友元，不意味着 B 是 A 的友元
2. **不具有传递性**：A 是 B 的友元、B 是 C 的友元，不意味着 A 是 C 的友元
3. **不能被继承**：父类的友元关系不会传递给子类
4. **破坏封装性**：应谨慎使用，能用公有接口解决就不加友元

## 12-6 友元的优缺点

**优点**

- 提高灵活性，允许特定函数/类访问非公有成员
- 简化某些复杂场景的代码（如流运算符重载、两个类紧密协作）

**缺点**

- 破坏封装性，增加代码耦合
- 可能导致代码难以维护和测试
- 友元关系不可控扩散（友元类可访问全部成员）

> 工程建议：友元应视为「设计妥协」，仅在必须时使用（典型必要场景：`operator<<`/`operator>>`、需要访问两个类私有成员的二元运算、测试类）。

# 第13章 运算符重载

## 13-1 左值（lvalue）与右值（rvalue）

**左值**：表示一个对象的表达式，具有**确定的内存地址**，可出现在赋值语句**左边**；简单说就是**可以取地址**的表达式。

- 特点：可以被赋值；可以取地址

**右值**：不表示持久对象的表达式，通常是**临时对象或字面量**，不能出现在赋值左边，**不能取地址**。

- 特点：不能被赋值；不能取地址

```cpp
int a = 10;              // a 是左值
char b = (char)(a + 5);  // a+5 的结果是右值
int& r = a;              // ✅ 左值引用绑定左值
// int& r2 = 10;         // ❌ 左值引用不能绑右值
const int& r3 = 10;      // ✅ 常引用可以绑右值（生命周期延长）
int&& r4 = 10;           // ✅ 右值引用（C++11）
```

**运算符重载中为什么要关心左右值**：决定了重载函数的返回类型（值 / 引用）与参数类型（`T` / `T&` / `const T&` / `T&&`）。

## 13-2 运算符重载简介

**定义**：为自定义类型重新定义已有运算符的行为，使其能操作自定义类型对象。

**目的**：让代码更直观简洁，提升可读性和可维护性（`a + b` 比 `a.add(b)` 自然）。

**四条限制（考点）**

1. **不能创建新运算符**（不能定义 `**`、`<>` 等）
2. **不能改变运算符的优先级和结合性**
3. **不能改变运算符的操作数个数**（双目仍双目）
4. **部分运算符不能重载**：`::` `.*` `.` `sizeof` `?:`（部分编译器）/ `typeid`
   - 另外 `=`、`[]`、`()`、`->` **只能**作为成员函数重载

**可重载运算符（常用）**

```
+ - * / % ^ & | ~ ! = < > += -= *= /= %= ^= &= |=
<< >> <<= >>= == != <= >= ++ -- ->* , [] () new delete
```

## 13-3 两种实现方式

### 方式一：成员函数版本

```cpp
返回类型 operator#(参数列表) { }
```

**特点**

- `this` 指向调用对象，因此**左操作数默认为当前对象**
- 天然可访问类私有成员
- **参数个数规则**：
  - 单目运算符（`++ -- - ! ~`）：参数列表为空
  - 双目运算符（`+ - * / ==`）：参数列表**只有一个**（右操作数）

```cpp
class Complex {
public:
    Complex operator+(const Complex& r) const {     // 成员版双目 +
        return Complex(m_r + r.m_r, m_i + r.m_i);
    }
private:
    double m_r, m_i;
};

Complex a, b, c;
c = a + b;      // 等价于 a.operator+(b)
```

### 方式二：友元（全局）函数版本

```cpp
friend 返回类型 operator#(参数列表);    // 类内声明
// 类外定义
返回类型 operator#(参数列表) { }
```

**特点**

- 需要声明为友元才能访问非公有成员
- 适合**操作数类型不同**的场景（如 `2 + obj`、`cout << obj`）
- **参数个数规则**：
  - 双目运算符：**两个**操作数都作为参数
  - 单目运算符：**一个**参数

```cpp
class Complex {
public:
    friend Complex operator+(const Complex& L, const Complex& R);
private:
    double m_r, m_i;
};

Complex operator+(const Complex& L, const Complex& R) {
    return Complex(L.m_r + R.m_r, L.m_i + R.m_i);
}
```

**如何选（决策）**

| 场景                                             | 推荐             |
| ------------------------------------------------ | ---------------- |
| 需要左操作数是本类对象、且要访问私有成员         | 成员函数         |
| 左操作数可能是其他类型（`int + obj`）、`<<`/`>>` | 友元全局函数     |
| `=` `[]` `()` `->`                               | **必须**成员函数 |
| 保持对称性（`a+b` 与 `b+a` 都可用）              | 友元全局函数     |

## 13-4 双目运算符重载

常见：`+ - * / % == != > < >= <=`

**表达式 `L # R`**

- `L` 左操作数，`#` 运算符，`R` 右操作数
- 左右操作数**既可以是左值也可以是右值**
- **表达式的结果必须是右值**（不能对 `a+b` 的结果取地址或赋值）

```cpp
int a = 10;                 // a 左值
char b = (char)(a + 5);     // a+5 结果为右值
sum = 100 + 200;            // 100+200 是右值
```

**标准签名（记熟这两个模板）**

成员函数版：

```cpp
// 算术类：返回新对象（值），常函数，参数常引用
const 类名 operator#(const 类名& R) const;

// 关系类：返回 bool
bool operator#(const 类名& R) const;
```

全局函数版：

```cpp
friend const 类名 operator#(const 类名& L, const 类名& R);
friend bool      operator#(const 类名& L, const 类名& R);
```

```cpp
class Complex {
public:
    Complex(double r = 0, double i = 0) : m_r(r), m_i(i) { }

    // 算术：成员版
    const Complex operator+(const Complex& R) const {
        return Complex(m_r + R.m_r, m_i + R.m_i);
    }
    // 关系：成员版
    bool operator==(const Complex& R) const {
        return m_r == R.m_r && m_i == R.m_i;
    }
    // 算术：全局友元版（支持 2 + c）
    friend const Complex operator*(double L, const Complex& R);
private:
    double m_r, m_i;
};

const Complex operator*(double L, const Complex& R) {
    return Complex(L * R.m_r, L * R.m_i);
}
```

> 为什么返回 `const 类名`（值）：防止 `(a + b) = c` 这种给右值赋值；C++11 之后对内置类型也如此，但现代实践多用「返回值 + 移动语义」，`const` 返回值会阻止移动优化，可按团队规范取舍。

## 13-5 单目运算符重载

常见：`-`（负号）、`!`（逻辑非）、`~`（按位取反）

**表达式 `#O`**

- 操作数既可以是左值也可以是右值
- **表达式结果一定是右值**

```cpp
int a = 5;
b = -a;         // a 是左值
b = -(a + 3);   // a+3 是右值
int c = ~a;     // 结果是右值
```

**签名**

```cpp
// 成员函数版
const 类名 operator#() const;

// 全局函数版
friend const 类名 operator#(const 类名& O);
```

```cpp
class Complex {
public:
    const Complex operator-() const {           // 成员版负号
        return Complex(-m_r, -m_i);
    }
    bool operator!() const {                    // 成员版逻辑非
        return (m_r == 0 && m_i == 0);
    }
private:
    double m_r, m_i;
};
```

## 13-6 赋值类运算符重载

常见：`=`、`+=`、`-=`、`*=`、`/=`

**表达式 `L # R`**

- **左操作数只能是左值**（`100 += b` 报错）
- 右操作数既可以是左值也可以是右值
- **返回值是左操作数自身（引用）**，因此支持链式

**签名**

```cpp
// 成员函数版
类名& operator#(const 类名& R);

// 全局函数版
friend 类名& operator#(类名& L, const 类名& R);
```

```cpp
class Complex {
public:
    Complex& operator+=(const Complex& R) {
        m_r += R.m_r;
        m_i += R.m_i;
        return *this;               // 返回自身引用
    }
private:
    double m_r, m_i;
};

Complex a, b;
(a += b) += b;      // 链式，因为返回引用
```

**`=` 的特例（拷贝赋值）**

```cpp
类名& operator=(const 类名& other) {
    if (this != &other) {        // 必须自赋值检查
        // 释放旧资源 + 深拷贝
    }
    return *this;
}
```

## 13-7 自增自减运算符重载

### 前置 `++i` / `--i`（表达式 `#O`）

- 操作数是**左值**
- **返回值是左值（引用）**
- `++a = 10;` 合法（虽然一般不这么写）

```cpp
// 成员版
类名& operator#(void);
// 全局版
friend 类名& operator#(类名& O);
```

```cpp
class Int {
public:
    Int& operator++() { ++m_v; return *this; }    // 前置：先加再返回自身
private:
    int m_v = 0;
};
```

### 后置 `i++` / `i--`（表达式 `O#`）

- 操作数是**左值**
- **返回值是右值（值，副本）**，返回的是**修改前的值**

```cpp
// 成员版
const 类名 operator#(哑元);
// 全局版
friend const 类名 operator#(类名& O, 哑元);
```

```cpp
class Int {
public:
    Int operator++(int) {              // int 是哑元，用于区分前置/后置
        Int tmp = *this;               // 先保存原值
        ++m_v;                         // 再自增
        return tmp;                    // 返回原值副本
    }
private:
    int m_v = 0;
};

Int i;
++i;        // 调 operator++()
i++;        // 调 operator++(int)，哑元不用实际传参
```

> **哑元参数的作用**：仅用于**占位/区分重载**，调用时不必传值。可以是任意类型，惯例用 `int`。

**前置 vs 后置对比（考点）**

| 特性           | 前置 `++i` `--i`         | 后置 `i++` `i--`             |
| -------------- | ------------------------ | ---------------------------- |
| 返回值类型     | 引用（变量本身）         | 值（临时副本）               |
| 操作顺序       | 先修改，再返回           | 先保存原值，再修改，返回原值 |
| 设计目的       | 返回修改后的值，支持链式 | 返回原始值，符合内置语义     |
| 是否影响原变量 | 直接修改                 | 修改，但返回旧值             |
| 是否支持链式   | ✅（返回引用）            | ❌（返回副本）                |
| 性能           | 更优（无副本）           | 稍差（构造副本）             |

## 13-8 插入/提取运算符重载

**插入 `<<`**：把对象数据输出到流

```cpp
friend std::ostream& operator<<(std::ostream& out, const 类名& obj);
```

**提取 `>>`**：从流读入数据到对象

```cpp
friend std::istream& operator>>(std::istream& in, 类名& obj);
```

```cpp
#include <iostream>

class Complex {
public:
    Complex(double r = 0, double i = 0) : m_r(r), m_i(i) { }

    friend std::ostream& operator<<(std::ostream& out, const Complex& c) {
        out << c.m_r << (c.m_i >= 0 ? "+" : "") << c.m_i << "i";
        return out;
    }

    friend std::istream& operator>>(std::istream& in, Complex& c) {
        in >> c.m_r >> c.m_i;
        return in;
    }
private:
    double m_r, m_i;
};

Complex c(1, -2);
std::cout << c << std::endl;        // "1-2i"
std::cin  >> c;                     // 读入两个 double
```

**三条必须记住的规则**

1. **必须**用全局函数（流对象在左边，成员版无法让 `cout` 当左操作数）
2. **必须**声明为友元（要访问私有成员）
3. **返回流对象的引用**，以支持链式：`cout << a << b << c;`
4. `>>` 的第二个参数必须是**非 const 引用**（要写入对象）

## 13-9 运算符重载总结

**收益**

- **提高可读性**：`obj1 + obj2` 比 `obj1.add(obj2)` 直观
- **增强表达能力**：自定义类型可像内置类型一样操作（`cout << obj`、`cin >> obj`）
- **支持链式操作**：返回引用的设计让 `a += b += c` 成为可能
- **减少代码冗余**：`+=` 简化累加
- **扩展语言功能**：`==`/`!=` 实现对象相等比较

**风险与规范**

- 不要滥用：语义不清晰的运算符（如给 `+` 定义「删除」）会让代码更难懂
- 保持与内置语义一致：`+` 不该修改操作数；`++` 应自增
- 注意 const 正确性：不改对象的运算应为 `const` 成员函数
- 成对实现：`==` 与 `!=`、`<` 与 `>` 等应保持一致

# 第14章 继承

## 14-1 继承的基本概念与语法

**定义**：面向对象编程（OOP）的三大特性之一（封装、继承、多态）。用于描述类与类之间的关系，允许一个类（**派生类/子类**）继承另一个类（**基类/父类**）的属性和行为。

**举例**：游戏里所有英雄都有生命值、攻击力等通用属性，封装为基类 `Hero`；每个英雄特有的技能（打野、防守）封装为派生类。

**作用**

- **代码复用**：派生类直接使用基类成员，减少重复
- **多态的基础**：继承是实现运行时多态的前提

**语法**

```cpp
class 基类类名 {
    // 基类成员
};

class 派生类类名 : 继承方式 基类类名 {
    // 派生类成员
};
```

```cpp
class Hero {
public:
    int  hp;
    int  attack;
    void move() { cout << "move\n"; }
};

class Archer : public Hero {      // public 继承
public:
    void shoot() { cout << "shoot\n"; }
};

Archer a;
a.hp = 100;      // 继承来的
a.move();        // 继承来的
a.shoot();       // 自己的
```

## 14-2 继承方式与权限控制

**三种继承方式对基类成员的「权限降级」**

| 继承方式    | 基类 public 成员 | 基类 private 成员        | 基类 protected 成员 |
| ----------- | ---------------- | ------------------------ | ------------------- |
| `public`    | public           | **不可访问**（但被继承） | protected           |
| `private`   | private          | 不可访问                 | private             |
| `protected` | protected        | 不可访问                 | protected           |

**三条关键结论（必考）**

1. **基类 private 成员始终不可被子类访问**，但它**确实被继承了**（存在于子类对象内存中），只是无权访问
2. `private` 继承会把基类所有可访问成员降为 private
3. **推荐使用 `public` 继承**，便于理解与维护（这也是 99% 的场景）

> 记忆表：继承方式只会「收紧」不会「放宽」；取「继承方式」与「原权限」中**更严格**的那个（private 最严，public 最宽，但 private 成员始终不可见）。

**访问控制细则**

- 基类 `public` 成员：类外可访问
- 基类 `protected` 成员：**只能在派生类内部**访问，类外不可
- 基类 `private` 成员：**只能在基类内部**访问

**派生类访问基类成员**

```cpp
class Base {
public:    int  a;
protected: int  b;
private:   int  c;
};

class Derived : public Base {
public:
    void f() {
        a = 1;          // ✅ public 成员，类内可访问
        b = 2;          // ✅ protected 成员，派生类内可访问
        // c = 3;       // ❌ private 成员，不可访问
    }
};

Derived d;
d.a = 10;               // ✅ 类外可访问 public 继承来的 a
// d.b = 20;            // ❌ 类外不可访问 protected
```

**在类外访问基类成员**（有歧义时）

```cpp
class A { public: int v = 1; };
class B { public: int v = 2; };
class C : public A, public B { };

C c;
// c.v = 3;              // ❌ 歧义：A::v 还是 B::v
c.A::v = 3;              // ✅ 用 类名:: 明确指定
```

## 14-3 继承中的特殊成员函数

### 构造函数

**调用规则**

- 子类构造函数若**未显式调用**父类构造函数 → 编译器自动调用父类的**默认构造函数**
- 子类若**显式调用** → 优先调用显式指定的父类构造函数
- 若父类**没有默认构造函数**（只定义了有参构造）而子类又没显式调用 → **编译错误**

**调用顺序**：**先父类构造，再子类构造**

**语法**

```cpp
class 子类 : 继承方式 父类 {
    子类(形参) : 父类(形参), 子类成员变量(形参) { }
};
```

```cpp
class Base {
public:
    Base(int x) : m_x(x) { cout << "Base ctor\n"; }
private:
    int m_x;
};

class Derived : public Base {
public:
    Derived(int x, int y) : Base(x), m_y(y) {    // 必须显式调用 Base(x)
        cout << "Derived ctor\n";
    }
private:
    int m_y;
};

Derived d(1, 2);      // Base ctor → Derived ctor
```

### 析构函数

**调用规则**

- 未显式定义 → 编译器提供默认析构
- 显式定义 → 调用显式版本
- **调用顺序：先子类析构，再父类析构**（与构造严格相反）

```cpp
class Base { public: ~Base() { cout << "~Base\n"; } };
class Derived : public Base { public: ~Derived() { cout << "~Derived\n"; } };

Derived d;    // 构造: Base → Derived；析构: ~Derived → ~Base
```

> **重要**：若通过基类指针 `delete` 派生类对象，基类析构必须是 `virtual`，否则只调基类析构（见第 15 章）。

### 拷贝构造函数

**调用规则**

- 子类拷贝构造若**未显式调用**父类拷贝构造 → 编译器调用父类的**默认（拷贝）构造函数**
- 显式调用 → 优先用显式指定的
- **调用顺序：先父类拷贝构造，再子类拷贝构造**

**语法**

```cpp
class 子类 : 继承方式 父类 {
    子类(const 子类& obj) : 父类(obj), 子类成员变量(obj.成员变量) { }
};
```

> ⚠️ **高频坑**：`父类(obj)` 里传的是子类对象，但因为子类对象可**向上转型（切片）**为基类引用，实际调用的是父类的拷贝构造函数 —— 这是正确写法，不要写成 `父类(static_cast<const 父类&>(obj))`（也能用，但没必要）。

```cpp
class Base {
public:
    Base() { }
    Base(const Base& b) : m_x(b.m_x) { cout << "Base copy\n"; }
private:
    int m_x = 0;
};

class Derived : public Base {
public:
    Derived(const Derived& d) : Base(d), m_y(d.m_y) { cout << "Derived copy\n"; }
private:
    int m_y = 0;
};
```

### 拷贝赋值函数

**调用规则**

- 子类未显式调用父类拷贝赋值 → 编译器调用父类默认拷贝赋值（**注意：不会自动调用**，必须显式写）
- **调用顺序：先子类拷贝赋值，再父类拷贝赋值**

**语法**

```cpp
class 子类 : 继承方式 父类 {
    子类& operator=(const 子类& obj) {
        if (this != &obj) {
            父类::operator=(obj);         // 显式调用父类拷贝赋值
            成员变量名 = obj.成员变量名;    // 赋值子类成员
        }
        return *this;
    }
};
```

> 记忆：**构造函数/拷贝构造 → 父类先；析构 → 子类先；拷贝赋值 → 子类先。**

## 14-4 继承中的静态成员

**静态成员变量的继承**

- 子类可以访问父类的静态成员变量，可直接调用
- 若子类定义了**同名**静态成员变量 → 发生「**隐藏**」现象，子类的会隐藏父类的
- 父类的仍可通过 `父类名::成员` 显式访问

**静态成员函数的继承**

- 子类可继承父类静态方法，直接调用
- 同名静态方法同样发生「**隐藏**」，而**不是重写**（静态函数不能是虚函数）

```cpp
class Base {
public:
    static int  s_count;
    static void show() { cout << "Base show\n"; }
};
int Base::s_count = 0;

class Derived : public Base {
public:
    static int  s_count;                     // 隐藏 Base::s_count
    static void show() { cout << "Derived show\n"; }   // 隐藏 Base::show
};
int Derived::s_count = 0;

Derived::show();         // Derived show
Base::show();            // Base show（显式指定）
Derived::Base::show();   // 也可用 类名:: 访问被隐藏的父类版本
```

**四条注意（考点）**

1. 同名静态成员（变量/函数）只发生**隐藏**，不是重写
2. 被隐藏的父类静态成员仍可通过 `父类名::` 访问
3. **静态成员函数不支持多态**：属于类本身，不依赖对象，无法运行时绑定
4. **访问权限**：只有非私有（public/protected）的静态成员才能被子类继承和访问

## 14-5 多重继承

**定义**：一个子类同时继承**多个父类**的属性和方法。

**特点**：子类可从多个父类继承成员变量和成员函数；需注意**同名成员的冲突问题**。

**语法（两种写法）**

```cpp
// 方式一（推荐：每个父类都写继承方式，清晰）
class A {};
class B {};
class C : public A, public B { };

// 方式二（不写则默认 private 继承，容易出错，不推荐）
class C2 : public A, B { };     // B 是 private 继承！
```

```cpp
class Engine {
public:
    void start() { cout << "engine start\n"; }
};
class Wheel {
public:
    void roll() { cout << "wheel roll\n"; }
};
class Car : public Engine, public Wheel {
public:
    void run() { start(); roll(); }    // 直接用两个父类的成员
};
```

**同名成员冲突处理**

```cpp
class A { public: int v = 1; };
class B { public: int v = 2; };
class C : public A, public B { };

C c;
// c.v = 3;        // ❌ 二义性
c.A::v = 3;        // ✅ 明确指定
```

## 14-6 链式继承、扇形继承、菱形继承

### 链式继承（单链）

子类依次从父类继承，形成链条结构；每个子类只继承**一个**直接父类，通过多层继承间接访问更上层基类成员。

```cpp
class A {};
class B : public A {};
class C : public B {};      // A → B → C
```

### 扇形继承（多父、无关系）

一个子类同时继承多个父类，但这些父类之间**没有**继承关系。用于功能组合。

```cpp
class A {};      // A类   B类
class B {};
class C : public A, public B {};    // 汇到 C类
```

### 菱形继承（钻石继承）

两个子类分别从**同一个基类**派生，另一个类又同时继承这两个子类。

```cpp
class A {};                              //   A
class B : public A {};                   //  B   C
class C : public A {};
class D : public B, public C {};         //   D
```

**两个问题（核心考点）**

1. **公共基类子对象在汇聚子类中存在多份实例**：`D` 中会有 `A` 的两份副本（`B::A` 和 `C::A`），浪费内存
2. **访问歧义**：通过 `D` 访问 `A` 的成员时，因继承路径不同导致**二义性**编译错误

```cpp
class A { public: int v = 1; };
class B : public A {};
class C : public A {};
class D : public B, public C {};

D d;
// d.v = 2;        // ❌ 二义性：B::A::v 还是 C::A::v？
d.B::v = 2;        // 语法上可以，但语义上仍是两份 A
```

**解决方法：虚继承**（下一节）。

## 14-7 虚继承（virtual inheritance）

**定义**：在继承时使用 `virtual` 关键字，主要目的解决多继承中的**二义性问题**，确保基类**只被继承一次**，即使存在多条继承路径。

**原理**：虚继承的基类（虚基类）在汇聚子类中只有**一份**共享实例，中间类通过虚基类表指针（vbptr）访问它。

**语法**

```cpp
class 基类 {};                                    // 虚基类
class 子类1 : virtual public 基类 {};             // 虚继承
class 子类2 : virtual public 基类 {};             // 虚继承
class 汇聚子类 : public 子类1, public 子类2 {};    // 汇聚
```

```cpp
class A { public: int v = 1; };
class B : virtual public A {};
class C : virtual public A {};
class D : public B, public C {};

D d;
d.v = 2;        // ✅ 无歧义，只有一份 A
```

**虚继承的作用**

1. **解决多份祖先数据问题**：避免基类被多次继承带来的二义性和内存浪费
2. **共享同一份祖先数据**：所有路径共享同一份基类实例

**构造函数注意事项（高频考点）**

- 菱形继承中，**虚基类的构造函数不会由中间类自动调用**，必须由**最派生类（汇聚子类）显式调用**
- 未显式调用 → 编译报错「没有显式调用虚基类的构造函数」
- **原因**：虚基类的初始化责任由**最派生类**承担，中间子类对虚基类构造的调用会被忽略

```cpp
class A {
public:
    A(int x) : m_x(x) { }
private:
    int m_x;
};

class B : virtual public A {
public:
    B(int x) : A(x) { }        // 这里的 A(x) 在 D 构造时会被忽略
};

class C : virtual public A {
public:
    C(int x) : A(x) { }
};

class D : public B, public C {
public:
    D(int x) : A(x), B(x), C(x) { }   // ✅ 必须在这里显式构造虚基类 A
};
```

> 代价：虚继承会增加一次间接寻址（vbptr），有轻微空间与性能开销；没有菱形问题就不要用。

# 第15章 多态

## 15-1 虚函数

**定义**：在基类中用 `virtual` 关键字声明的函数，允许在派生类中**重写**（override）。

**语法**

```cpp
class Base {
public:
    virtual 返回值类型 函数名(参数列表) {
        // 函数体
    }
};
```

```cpp
class Base {
public:
    virtual void show() { cout << "Base\n"; }
};

class Derived : public Base {
public:
    void show() override { cout << "Derived\n"; }   // virtual 可省略
};
```

**作用：动态绑定**
通过**基类指针或引用**调用派生类的重写函数，实现**运行时多态**。

```cpp
Derived d;
Base* p = &d;
p->show();          // 输出 "Derived"（动态绑定到派生类版本）

Base& r = d;
r.show();           // 同上
```

**四条注意（考点）**

1. 派生类重写时 **`virtual` 关键字可省略**，但**仍然是虚函数**（virtual 属性会沿继承链传递）
2. 重写必须满足：**函数名、参数列表、返回类型**（或协变返回类型）都要相同
3. 只有**通过指针或引用**调用才有多态；**通过对象直接调用**是静态绑定
4. 构造函数不能是虚函数；析构函数**应该**是虚函数（见 15-4）

**`override` 与 `final`（C++11）**

```cpp
class Derived : public Base {
public:
    void show() override;      // 编译器检查是否真的重写了基类虚函数（推荐必写）
    void other() final;        // 禁止后续派生类重写
};
```

## 15-2 函数重写（override）

**定义**：在派生类中重新定义基类中的虚函数（函数名、参数列表、返回值必须相同）。

**特点**

- 发生在**基类和派生类之间**
- 基类函数**必须**用 `virtual` 声明（否则是「隐藏」而非「重写」）

```cpp
class Base {
public:
    virtual void show() { cout << "Base class\n"; }
};

class Derived : public Base {
public:
    void show() { cout << "Derived class\n"; }   // 重写
};
```

**函数重载 vs 函数重写（高频对比表）**

| 特性         | 函数重载（overload） | 函数重写（override）       |
| ------------ | -------------------- | -------------------------- |
| 定义位置     | **同一作用域内**     | **父类与子类之间**         |
| 函数名       | 必须相同             | 必须相同                   |
| 参数列表     | **必须不同**         | **必须相同**               |
| 返回值类型   | 不影响重载判定       | 必须相同（或协变返回类型） |
| 绑定时机     | 静态绑定（编译期）   | 动态绑定（运行期）         |
| 依赖 virtual | 不需要               | 基类必须 virtual           |
| 目的         | 同一接口处理不同参数 | 派生类改写基类行为         |

**三种「像但不同」的概念（必考）**

| 概念          | 条件                                           | 结果                                            |
| ------------- | ---------------------------------------------- | ----------------------------------------------- |
| 重载 overload | 同作用域、同名、参数不同                       | 编译期选版本                                    |
| 重写 override | 父子类、同名、参数相同、基类 virtual           | 运行期多态                                      |
| 隐藏 hide     | 父子类、同名、**基类非 virtual**（或参数不同） | 静态绑定，调基类版本；可用 `Base::f()` 显式调用 |

```cpp
class Base {
public:
    void f(int)    { cout << "Base::f(int)\n"; }
    virtual void g(int) { cout << "Base::g\n"; }
};

class Derived : public Base {
public:
    void f(int)    { cout << "Derived::f(int)\n"; }   // 隐藏（非 virtual）
    void g(int)    { cout << "Derived::g\n"; }        // 重写（virtual）
    void g(double) { cout << "Derived::g(double)\n"; } // 这会隐藏基类所有 g！要加 using Base::g;
};

Derived d;
Base* p = &d;
p->f(1);      // Base::f(int)   ← 静态绑定
p->g(1);      // Derived::g     ← 动态绑定
d.g(1.5);     // Derived::g(double)
// d.g(1);    // 若 Derived 只写了 g(double)，基类 g(int) 被隐藏 → 报错或调 double 版
```

> 经验：派生类中要重写就写 `override`；如果只是加一个同名重载，记得 `using Base::f;` 把基类版本引入作用域。

## 15-3 多态

**定义**：同一接口在不同情况下表现出不同的行为。分两类：

| 类型                       | 绑定时机   | 实现手段                   |
| -------------------------- | ---------- | -------------------------- |
| **静态多态**（编译期多态） | 编译时绑定 | 函数重载、模板、运算符重载 |
| **动态多态**（运行期多态） | 运行时绑定 | 虚函数 + 基类指针/引用     |

**动态多态四个必要条件（必背）**

1. **继承关系**：基类与派生类之间存在继承
2. **虚函数**：基类中声明 `virtual`
3. **重写**：派生类中重写基类虚函数（签名一致）
4. **基类指针或引用**：用基类指针/引用指向派生类对象

缺任何一个都不构成动态多态。

**实现机制：虚函数表 vtable + 虚函数指针 vptr**

```
对象内存布局（含虚函数时）：
┌─────────────┐
│  vptr ──────┼──→ ┌──────────────────────┐
├─────────────┤    │ 0: &Base::print()    │  ← 虚函数表 vtable
│  成员变量    │    │ 1: &Base::other()    │
└─────────────┘    └──────────────────────┘
```

- 每个**含虚函数的类**有一张**虚函数表 vtable**（存虚函数地址，编译期生成，全类共享）
- 每个**对象**有一个隐藏的 **vptr**（指向所属类的 vtable，构造时设置），64 位下占 8 字节
- 调用 `p->print()` 实际是：`p->vptr[0](p)` → **间接调用**，因此是运行时绑定

```cpp
class Base {
public:
    virtual void print() { cout << "Base\n"; }
    virtual void other() { }
};

class Son1 : public Base { public: void print() { cout << "Son1\n"; } };
class Son2 : public Base { public: void print() { cout << "Son2\n"; } };

Son1 s1; Son2 s2;

Base* p1 = &s1;   p1->print();   // Son1（p1->vptr 指向 Son1 的 vtable）
Base* p2 = &s2;   p2->print();   // Son2

Base& r = s1;     r.print();     // Son1（引用本质也是指针）
```

**代价**

- 每个对象多一个 vptr（空间成本）
- 每次虚调用多一次间接寻址（无法内联，性能成本）
- 不要给不需要多态的类加虚函数

**静态绑定 vs 动态绑定验证**

```cpp
Son1 s1;
Base b = s1;        // ⚠️ 对象切片：只拷贝了 Base 部分，b 是真正的 Base 对象
b.print();          // 输出 "Base"，不是 Son1

Base& r = s1;       // 引用不切片
r.print();          // 输出 "Son1"
```

> 这是「**对象切片（object slicing）**」问题：按值把派生类赋给基类对象会丢失派生部分，多态失效。**多态必须用指针或引用**。

## 15-4 虚析构函数

**定义**：一种特殊的虚函数，用于确保通过**基类指针或引用删除派生类对象**时，能正确调用派生类的析构函数。

**语法**

```cpp
class Base {
public:
    virtual ~Base() { }      // 虚析构
};
```

**作用**

1. **防止内存泄漏**：用基类指针 `delete` 派生类对象时，若无虚析构，**只会调用基类析构**，派生类的资源（`new` 出来的内存）不会被释放
2. **保证行为安全**：正确调用所有层次的析构函数，避免未定义行为

```cpp
class Base {
public:
    ~Base() { cout << "~Base\n"; }          // ❌ 非虚
};

class Derived : public Base {
public:
    Derived() : p(new int[100]) { }
    ~Derived() { delete[] p; cout << "~Derived\n"; }   // 不会被调用！
private:
    int* p;
};

Base* p = new Derived;
delete p;      // 只输出 "~Base"，Derived 的 p 泄漏 → 内存泄漏 + UB
```

```cpp
class Base2 {
public:
    virtual ~Base2() { cout << "~Base\n"; }   // ✅ 虚析构
};

Base2* q = new Derived2;
delete q;      // ~Derived → ~Base，正确
```

**三条规则（必背）**

1. **作为基类的类，析构函数应声明为 `virtual`**（哪怕它什么都不做）
2. 一旦基类析构是 virtual，所有派生类析构自动是 virtual
3. 如果类不会被当做基类使用（或不会被 `delete`），可以不用虚析构（省 vptr 开销）

> 组合记忆：**虚函数为了「行为多态」，虚析构为了「资源正确释放」**。含虚函数的类几乎都必须虚析构。

## 15-5 纯虚函数与抽象类

**纯虚函数定义**：在基类中**声明但没有实现**的虚函数。

**声明格式**

```cpp
virtual 返回类型 函数名(参数列表) = 0;
```

```cpp
class Shape {
public:
    virtual double area() const = 0;      // 纯虚函数
    virtual void   draw()  const = 0;
};
```

**纯虚函数特点**

1. 包含纯虚函数的类称为**抽象类**
2. **抽象类不能实例化**，只能作为基类被继承
3. 派生类**必须重写所有纯虚函数**，否则派生类仍然是抽象类

**抽象类定义**：包含**至少一个**纯虚函数的类。

**作用**：提供统一的**接口规范**（类似「合同」），强制派生类实现。

**特点**

1. 抽象类**不能创建对象**
2. **强制**要求派生类实现所有纯虚函数

```cpp
class Shape {
public:
    virtual double area() const = 0;
    virtual ~Shape() { }                   // 抽象基类也要虚析构
};

class Rect : public Shape {
public:
    Rect(double w, double h) : m_w(w), m_h(h) { }
    double area() const override { return m_w * m_h; }
private:
    double m_w, m_h;
};

class Circle : public Shape {
public:
    Circle(double r) : m_r(r) { }
    double area() const override { return 3.14159 * m_r * m_r; }
private:
    double m_r;
};

// Shape s;          // ❌ 不能实例化抽象类
Shape* shapes[] = { new Rect(2, 3), new Circle(1) };   // ✅ 用基类指针统一管理
for (auto s : shapes) cout << s->area() << endl;        // 多态调用
```

**补充**

- 纯虚函数**可以有函数体**（`virtual void f() = 0;` 之后可类外定义 `void Base::f(){}`），供派生类显式调用
- 抽象类可以有**普通成员变量、普通成员函数、构造函数**（构造函数用于派生类构造时初始化基类部分）
- 接口类：只有纯虚函数 + 虚析构的抽象类，常见于「面向接口编程」

**多态三兄弟关系总结**

| 概念     | 位置     | 关键字                | 效果                           |
| -------- | -------- | --------------------- | ------------------------------ |
| 重载     | 同作用域 | 无                    | 编译期选版本                   |
| 重写     | 父子类   | `virtual`（基类）     | 运行期多态                     |
| 隐藏     | 父子类   | 无 virtual / 参数不同 | 静态绑定，子类遮蔽父类         |
| 纯虚函数 | 基类     | `= 0`                 | 强制派生类实现，基类不可实例化 |

# 第16章 模板

## 16-1 模板简介

**定义**：C++ 中支持**泛型编程**的机制，允许编写**与类型无关**的通用代码，提高代码复用性。

**泛型编程核心思想**：**编写一次代码，适用于多种数据类型**。

**模板分类**

- **函数模板**：定义通用函数
- **类模板**：定义通用类

**意义**

- 减少代码重复
- 提高可维护性和可扩展性
- **增强类型安全性**（编译期检查，优于 `void*` + 宏）

**与「重载」的区别**：重载是手写 N 个版本；模板是写 1 个版本，编译器按需生成 N 个实体。

## 16-2 函数模板的定义

**定义**：用于定义通用函数，通过模板参数支持多种数据类型。

**语法**

```cpp
template <typename T>          // 或 template <class T>，二者等价
返回值类型 函数名(参数列表) {
    // 函数体
}
```

- `template`：声明模板
- `typename T`：定义模板参数，`T` 是类型占位符（可任意命名，惯例 `T`、`U`、`Key`、`Value`）

```cpp
template <typename T>
T max_of(T a, T b)
{
    return a > b ? a : b;
}

cout << max_of(3, 5) << endl;          // T = int
cout << max_of(2.5, 1.7) << endl;      // T = double
cout << max_of('a', 'z') << endl;      // T = char

// 多类型参数
template <typename T1, typename T2>
auto add(T1 a, T2 b) -> decltype(a + b)   // C++11 后可直接 auto
{
    return a + b;
}
```

**非类型模板参数（了解）**：模板参数不只是「类型」，也可以是编译期常量

```cpp
template <typename T, int N>
class FixedArray {
    T data[N];           // N 作为编译期常量使用
};
FixedArray<int, 10> arr; // 容量在编译期确定，无运行时开销
```

> 这也是 STL 中 `std::array<T, N>` 的实现原理。

## 16-3 函数模板的使用与实例化

**与普通函数的优先级（考点）**

1. 若同时存在函数模板和普通函数，**普通函数优先级更高**
2. 普通函数满足调用条件 → 优先调普通函数
3. 普通函数不满足 → 调函数模板

```cpp
template <typename T> T max_of(T a, T b) { return a > b ? a : b; }
int max_of(int a, int b) { cout << "normal\n"; return a > b ? a : b; }

max_of(1, 2);       // 调普通函数，输出 "normal"
max_of(1.5, 2.5);   // 调模板（普通函数不匹配 double）
max_of<>(1, 2);     // 强制走模板（<> 表示只要模板）
```

**调用模板的三种方式**

```cpp
max_of(3, 4);           // ① 隐式调用：编译器根据实参推导 T
max_of<>(3, 4);         // ② 显式调用但不指定类型：仍靠推导，同时排除普通函数
max_of<int>(3, 4);      // ③ 显式指定类型：明确 T = int
```

**模板分析：编译器行为**

| 问题                                           | 答案                                                       |
| ---------------------------------------------- | ---------------------------------------------------------- |
| 模板会被编译成「一个能处理任何类型的函数」吗？ | **不会**                                                   |
| 那怎么处理不同类型？                           | 每次实例化时，**为具体类型生成一个真正的函数实体**         |
| 模板本身是函数吗？                             | **不是函数实体**，只是一个「生成函数的图纸」               |
| 实例化是什么？                                 | 用**具体数据类型替换模板类型形参**的过程，产生一个函数实例 |
| 需要手动请求实例化吗？                         | 不需要，**只要使用模板就自动触发**（自动实例化）           |

```cpp
// 模板定义（一份）
template <typename T> T add(T a, T b) { return a + b; }

// 编译器生成（两份实体）
add(1, 2);        // → int    add_int(int, int)
add(1.1, 2.2);    // → double add_double(double, double)
```

> 后果：模板代码**必须写在头文件里**（或在使用它的翻译单元可见），否则链接期找不到实体（`undefined reference`）。这也是模板与普通函数「声明放头文件、定义放 cpp」的差别。

**每个实例化实体都是独立的**，各自占一份代码（**代码膨胀**）。同一类型只实例化一次（同一翻译单元内）。

## 16-4 类模板

**定义**：允许编写**通用的类**，支持多种数据类型，通过模板参数复用代码，避免每种类型写一个类。

**语法**

```cpp
template <typename 参数1, typename 参数2, ...>
class 类名 {
    // 类体
};

// 或用 class 代替 typename（等价）
template <class T>
class 类名 { };
```

```cpp
template <typename T>
class MyArray {
public:
    MyArray(int n) : m_data(new T[n]), m_n(n) { }
    ~MyArray() { delete[] m_data; m_data = nullptr; }

    T& operator[](int i) { return m_data[i]; }
    int size() const { return m_n; }

private:
    T* m_data;
    int m_n;
};
```

**使用：必须显式指定模板参数类型**

```cpp
MyArray<int>    a1(10);      // T = int
MyArray<double> a2(20);      // T = double
MyArray<std::string> a3(5);
```

**类模板的成员函数定义**（若写在类外，需要重复模板头）

```cpp
template <typename T>
T& MyArray<T>::operator[](int i)
{
    return m_data[i];
}

template <typename T>
int MyArray<T>::size() const { return m_n; }
```

**同名的类模板与普通类不能共存**

```cpp
template <typename T> class MyClass { };
class MyClass { };        // ❌ 编译错误：重定义
```

**类模板的静态成员**：**每个实例化类型各有一份**静态成员

```cpp
template <typename T>
class Counter {
public:
    static int count;
};
template <typename T> int Counter<T>::count = 0;

Counter<int>::count    = 1;    // int 版
Counter<double>::count = 2;    // double 版，互不影响
```

**类模板作为参数/模板的模板**

```cpp
template <template <typename> class Container, typename T>
class Wrapper { Container<T> c; };
```

**特化（了解）**

```cpp
template <> class MyArray<bool> { /* 针对 bool 的特殊实现，如位压缩 */ };
```

## 16-5 二次编译

**第一次编译**（实例化之前，即产生真正实体之前）

- 检查内容：
  1. **语法正确性**：模板内部代码是否符合基本语法，所有标识符是否有声明
  2. **已知类型的有效性**：对**已知类型**（非依赖名）的调用，检查是否有效
  3. **未知类型的合理性**：对**未知类型**（依赖模板参数）的调用，**默认认为合理**，不报错

**第二次编译**（实例化之后，产生真正实体之后）

- 检查内容：
  1. **结合类型实参**：按实际类型参数再次检查模板代码
  2. **有效性验证**：确保所有调用在该具体类型下都有效

**含义与后果（考点）**

- 模板里 `T` 相关的错误**不会在第一遍报出来**，只有实例化时才暴露 → 报错信息长、难定位
- 如果模板从未被实例化，即使里面有错误也可能**不报错**（这也是模板「隐性 bug」的来源）
- 实践建议：写模板时主动为常用类型写测试用例触发实例化；用 `static_assert` 在编译期断言类型约束

```cpp
template <typename T>
void f(T t)
{
    t.foo();        // 第一次编译：不知道 T，默认合理，不报错
}

f(1);               // 第二次编译：int 没有 foo() → 报错！
```

**C++20 concepts** 让这类约束在第一次编译时就能检查清楚：

```cpp
template <typename T>
requires requires(T t) { t.foo(); }
void f(T t) { t.foo(); }
```

# 第17章 标准模板库 STL

## 17-1 STL 简介

**定义**：STL（Standard Template Library）是 C++ 标准库的**核心组件**，提供通用、高效、可复用的**类模板和函数**，支持泛型编程。

**作用**

- **提升效率**：不必从头实现常用数据结构与算法
- **代码简洁**：标准化接口减少冗余（`push_back()` 替代手动扩容）
- **兼容性**：符合行业标准，便于团队协作与维护

**六大组件**

| 组件                 | 作用                                                         |
| -------------------- | ------------------------------------------------------------ |
| **容器** container   | 存储数据（`vector` `list` `map` `set` `deque`）              |
| **迭代器** iterator  | 连接容器与算法的桥梁，提供统一元素访问方式                   |
| **算法** algorithm   | 操作数据（`sort` `find` `for_each` `copy`）                  |
| **函数对象** functor | 行为类似函数的对象，用于自定义算法逻辑（比较规则）           |
| **分配器** allocator | 管理内存分配，控制容器内存行为（自定义内存池）               |
| **适配器** adapter   | 容器适配器（`stack` `queue` `priority_queue`）与迭代器适配器 |

## 17-2 容器概述

**定义**：存储和管理数据的对象，提供统一接口操作数据（插入、删除、访问）。

**三类容器**

| 分类           | 特点                         | 代表                                                         |
| -------------- | ---------------------------- | ------------------------------------------------------------ |
| **顺序容器**   | 线性存储，按顺序访问         | `vector` `deque` `list` `forward_list` `array`               |
| **关联容器**   | 按键值对存储，自动排序或哈希 | `set` `map` `multiset` `multimap` `unordered_set` `unordered_map` |
| **容器适配器** | 基于其他容器实现特定功能     | `stack` `queue` `priority_queue`                             |

**选择依据（决策表）**

| 需求               | 推荐容器                          |
| ------------------ | --------------------------------- |
| 随机访问、尾部增删 | `vector`                          |
| 中间频繁插入/删除  | `list`                            |
| 头尾都要增删       | `deque`                           |
| 自动排序、去重     | `set` / `map`                     |
| 哈希查找、无需排序 | `unordered_set` / `unordered_map` |
| 后进先出           | `stack`                           |
| 先进先出           | `queue`                           |
| 优先级队列         | `priority_queue`                  |

**复杂度速记**

| 容器          | 随机访问 | 插入/删除                 | 查找                        |
| ------------- | -------- | ------------------------- | --------------------------- |
| `vector`      | O(1)     | 尾部 O(1) 均摊，中间 O(n) | O(n)（有序可二分 O(log n)） |
| `deque`       | O(1)     | 头尾 O(1)，中间 O(n)      | O(n)                        |
| `list`        | ❌ O(n)   | 已知位置 O(1)             | O(n)                        |
| `set/map`     | ❌        | O(log n)                  | O(log n)                    |
| `unordered_*` | ❌        | 平均 O(1)                 | 平均 O(1)                   |

## 17-3 迭代器概述

**定义**：迭代器是**访问容器元素的指针**，提供统一的遍历和操作接口，是**容器与算法之间的桥梁**。

**基本操作**

```cpp
++it / --it          // 移动
*it                  // 解引用，取元素值
it->member           // 访问对象元素的成员
c.begin() / c.end()  // 起止迭代器（end 是「最后一个元素之后」，不是最后一个元素）
```

```cpp
std::vector<int> v = {1, 2, 3, 4, 5};

for (std::vector<int>::iterator it = v.begin(); it != v.end(); ++it)
    std::cout << *it << " ";

// C++11 范围 for（底层就是迭代器）
for (int x : v) std::cout << x << " ";
```

**作用**

1. **连接容器与算法**：`std::sort(v.begin(), v.end())`
2. **统一访问方式**：不同容器通过迭代器提供一致的遍历接口

**五种迭代器类型**

| 类型                          | 支持操作                       | 典型容器                          |
| ----------------------------- | ------------------------------ | --------------------------------- |
| **输入**（input）             | 读取、单向 `++`                | 输入流、`vector` 只读             |
| **输出**（output）            | 写入、单向 `++`                | 输出流、`vector` 写入             |
| **前向**（forward）           | 读写、单向 `++`                | `forward_list`（`list` 也满足）   |
| **双向**（bidirectional）     | 读写、双向 `++ --`             | `list` `set` `map`                |
| **随机访问**（random access） | 读写、跳跃 `[n]` `<` `+n` `-n` | `vector` `deque` `string` `array` |

**迭代器失效（高频坑）**

- `vector` / `deque` 在**容量变化**（`push_back` 触发扩容）后，**所有**迭代器失效
- `vector` `erase(it)` 后，`it` 及之后的迭代器失效
- `list` `map` `set` 只在**被删除的那个**迭代器失效
- 解决：用 `it = v.erase(it);` 接收返回值

```cpp
std::vector<int> v = {1, 2, 3, 4};
for (auto it = v.begin(); it != v.end(); ) {
    if (*it == 2) it = v.erase(it);   // ✅ 正确：接住返回值
    else          ++it;
}
```

## 17-4 vector 容器

**定义与特性**

- `vector` 是**动态数组**，属于**顺序容器**，元素存储在**连续内存**中
- 支持**随机访问**（`[]` 或 `at()`）
- 所有元素**必须是相同类型**
- 自动扩容：元素数超过容量时申请更大内存，通常为原容量的 **1.5~2 倍**（`vector` 常见 2 倍，`MSVC` 为 1.5 倍）
- 可管理**容量（capacity）**与**元素数量（size）**两个概念

**定义方式**

```cpp
std::vector<int> v1;                       // 空容器
std::vector<int> v2 = {1, 2, 3};           // 初始化列表
std::vector<int> v3(5);                    // 5 个元素，值初始化 0
std::vector<int> v4(5, 10);                // 5 个元素，每个都是 10
std::vector<int> v5(v2);                   // 拷贝构造
std::vector<int> v6(v2.begin(), v2.end()); // 迭代器范围
```

**常用成员函数**

| 函数                                | 功能             | 说明                                              |
| ----------------------------------- | ---------------- | ------------------------------------------------- |
| `empty()`                           | 是否为空         | 返回 bool，比 `size()==0` 语义更好                |
| `size()`                            | 元素个数         | `size_t` 无符号，与 `int` 比较会有符号/无符号警告 |
| `capacity()`                        | 当前容量         | 不重新分配内存可容纳的元素数                      |
| `reserve(n)`                        | 预留容量         | 避免多次扩容，**推荐**在已知规模时调用            |
| `resize(n)`                         | 改变元素数       | 变大补默认值，变小截断                            |
| `operator[]`                        | 访问元素         | **不检查越界**，快                                |
| `at(n)`                             | 访问元素         | **检查越界**，越界抛 `std::out_of_range`          |
| `front()`                           | 首元素           |                                                   |
| `back()`                            | 末元素           |                                                   |
| `push_back(x)`                      | 尾部添加         | 均摊 O(1)                                         |
| `pop_back()`                        | 尾部删除         | **不返回值**                                      |
| `insert(pos, x)`                    | 指定位置插入     | O(n)                                              |
| `erase(pos)` / `erase(first, last)` | 删除元素/范围    | O(n)，返回下一元素迭代器                          |
| `clear()`                           | 清空所有元素     | **不释放容量**，`size` 变 0，`capacity` 不变      |
| `shrink_to_fit()`                   | 请求释放多余容量 | 非强制                                            |
| `swap(other)`                       | 交换两个容器     | O(1)，常用于「真正释放内存」                      |

```cpp
#include <vector>
std::vector<int> v;

v.push_back(10);
v.push_back(20);
v.emplace_back(30);        // C++11 原地构造，避免临时对象（对类类型更高效）

v.reserve(100);            // 预留 100 个空间，避免反复扩容

for (size_t i = 0; i < v.size(); ++i) std::cout << v[i] << " ";
std::cout << std::endl;

std::cout << v.front() << " " << v.back() << std::endl;

if (!v.empty() && v.size() > 3) std::cout << v.at(3) << std::endl;

v.insert(v.begin(), 0);            // 头部插入 O(n)
v.erase(v.begin());                 // 删除头部

v.clear();                          // 清空但保留容量
std::vector<int>().swap(v);         // 彻底释放内存（技巧）
```

**迭代器与遍历**

| 成员函数          | 返回类型           | 说明                                         |
| ----------------- | ------------------ | -------------------------------------------- |
| `begin()`         | `iterator`         | 指向第一个元素                               |
| `end()`           | `iterator`         | 指向**最后一个元素之后**的位置               |
| `rbegin()`        | `reverse_iterator` | 指向最后一个元素（反向遍历起点）             |
| `rend()`          | `reverse_iterator` | 指向第一个元素**之前**的位置（反向遍历终点） |
| `cbegin()/cend()` | `const_iterator`   | 只读迭代器（C++11）                          |

```cpp
for (auto it = v.begin(); it != v.end(); ++it) std::cout << *it;
for (auto rit = v.rbegin(); rit != v.rend(); ++rit) std::cout << *rit;   // 逆序
for (const auto& x : v) std::cout << x;    // 只读，避免拷贝
for (auto& x : v) x *= 2;                   // 可修改
```

**vector 六大坑（考点）**

| 坑                           | 说明                                                         |
| ---------------------------- | ------------------------------------------------------------ |
| `[]` 不检查越界              | 越界是 UB，可能读到垃圾或崩溃；需要安全检查用 `at()`         |
| `clear()` 不释放内存         | `capacity` 不变；要真释放用 `swap` 或 `shrink_to_fit()`      |
| 扩容导致迭代器/指针/引用失效 | 扩容后旧迭代器全部失效；**不要在循环里保存 `&v[0]` 跨 push_back 使用** |
| `pop_back()` 空容器调用      | UB                                                           |
| `size()` 是 `size_t`         | 与 `int` 混用会有符号警告；`v.size() - 1` 在 size=0 时会变成极大值 |
| 扩容的拷贝成本               | 已知规模时先 `reserve(n)`；用 `emplace_back` 减少临时对象    |

```cpp
// 典型越界陷阱
std::vector<int> v;
// for (int i = 0; i <= v.size() - 1; ++i)   // size()=0 时 0<=巨大数，越界！

// 安全写法
for (size_t i = 0; i < v.size(); ++i) { }
```

## 17-5 STL 算法与函数对象（补充）

```cpp
#include <algorithm>
#include <vector>
#include <iostream>

std::vector<int> v = {3, 1, 4, 1, 5, 9, 2, 6};

std::sort(v.begin(), v.end());                    // 升序
std::sort(v.begin(), v.end(), std::greater<int>());  // 降序（函数对象）

auto it = std::find(v.begin(), v.end(), 4);      // 查找
int cnt  = std::count(v.begin(), v.end(), 1);    // 计数
std::for_each(v.begin(), v.end(), [](int x) { std::cout << x << " "; });  // lambda

std::reverse(v.begin(), v.end());
std::vector<int>::size_type n = std::max_element(v.begin(), v.end()) - v.begin();
```

**Lambda 与函数对象**

```cpp
// 函数对象（仿函数）
struct Cmp {
    bool operator()(int a, int b) const { return a > b; }
};
std::sort(v.begin(), v.end(), Cmp{});

// C++11 lambda（更常用）
std::sort(v.begin(), v.end(), [](int a, int b) { return a > b; });
```

**常见算法复杂度**

- `sort`：O(n log n)
- `find` / `count` / `for_each`：O(n)
- `binary_search`（需有序）：O(log n)
- `lower_bound` / `upper_bound`（需有序）：O(log n)

# 附录 B 面试速记

## B-1 一句话回答

1. **引用与指针**：引用是别名，必须初始化、不可为空、不可改绑；指针是地址变量，可为空、可改指向、可算术运算。
2. **重载 / 重写 / 隐藏**：重载在同作用域靠参数不同（编译期）；重写在父子类靠 virtual + 同签名（运行期）；隐藏是父子类同名但非虚，静态绑定。
3. **深拷贝与浅拷贝**：浅拷贝只复制指针地址导致共享；深拷贝重新申请内存复制内容。含动态资源必须深拷贝。
4. **为什么基类析构要虚**：基类指针 delete 派生类对象时，非虚析构只会调基类析构，派生类资源泄漏。
5. **虚函数实现**：每个含虚函数的类有 vtable，每个对象有 vptr；调用时经 vptr 间接跳到实际函数（动态绑定）。
6. **为什么 `new` 比 `malloc` 好**：自动算大小、返回正确类型、自动构造/析构、可初始化。
7. **`const` 成员函数**：修饰 this 指针，承诺不修改成员，可被常对象调用，可与非常函数构成重载。
8. **静态成员**：属于类不属于对象，静态变量类外定义、全对象共享，静态函数无 this 只能访问静态成员。
9. **explicit 作用**：禁止单参构造函数的隐式类型转换。
10. **初始化列表的作用**：直接初始化，效率高，且是 const/引用/无默认构造成员的唯一初始化方式。

| protected | ✅    | ✅      | ❌    |
| private   | ✅    | ❌      | ❌    |

**表3 四大核心函数**

|          | 构造       | 析构       | 拷贝构造         | 拷贝赋值             |
| -------- | ---------- | ---------- | ---------------- | -------------------- |
| 时机     | 创建对象   | 销毁对象   | 用旧对象建新对象 | 旧对象赋给已存在对象 |
| 返回     | 无         | 无         | 无               | `类名&`              |
| 参数     | 灵活可重载 | 无         | `const 类名&`    | `const 类名&`        |
| 默认生成 | 是         | 是         | 是（浅）         | 是（浅）             |
| 关键注意 | 可重载     | 不重复释放 | 深拷贝           | 自赋值检查 + 深拷贝  |

**表4 前置/后置自增**

|      | `++i`        | `i++`                  |
| ---- | ------------ | ---------------------- |
| 返回 | 引用（自身） | 值（旧值副本）         |
| 顺序 | 先改后返回   | 先存旧值，改后返回旧值 |
| 链式 | 支持         | 不支持                 |
| 性能 | 好           | 稍差                   |

## B-3 现代 C++ 最佳实践清单

| 条目                                 | 说明                                 |
| ------------------------------------ | ------------------------------------ |
| 用 `const` / `const&` 表达只读       | 输入参数用 `const T&`                |
| 单参构造默认加 `explicit`            | 防止隐式转换                         |
| 重写虚函数一律加 `override`          | 编译器帮你校验                       |
| 作为基类 → 析构加 `virtual`          | 避免 delete 泄漏                     |
| 需要自定义析构/拷贝 → 三法则         | 全写或全 `= default/delete`          |
| 优先零法则                           | 用 string/vector/unique_ptr 管理资源 |
| 用 `nullptr` 替代 `NULL`             | 类型安全                             |
| 不在头文件 `using namespace`         | 避免污染                             |
| 用 `emplace_back` / `reserve`        | 减少临时对象与扩容                   |
| 用范围 for + `const&` 遍历           | 简洁且无拷贝                         |
| 用 `static_assert` 约束模板          | 编译期报错，早发现                   |
| 用 `std::unique_ptr` / `make_unique` | 自动释放，异常安全                   |
